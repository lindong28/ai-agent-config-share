# decision-review

骨架：**触发与 review 对象**（是不是一个决策 → 平凡则声明免审、就此结束）→ **喂什么**（六项决策事实 + 评审者自己的契约）→ **判据**（七条，评审者逐条作答）→ **执行**（Codex read-only，同步）→ **gate 裁决**（唯一一张处置表，出口三种）→ **输出**（决策连同作用域落 adr/）。每个阶段名即下方同名小节。

## 为什么存在

代码评审审的是"实现对不对"，它对"这个决定本身站不站得住"结构性失明——决策错误产出的代码通常完全正确地实现了那个错误。触发本 gate 的五条实例里，没有一条是代码缺陷，全部能通过 code review。

更关键的一点决定了本 gate 必须是**外部评审者**、而不是再往 user-scope CLAUDE.md 加一条自查规则：五条里有两条（判据无区分度、结论作用域超出证据作用域）本就落在那里的「取证的充分性」已覆盖的范围内，规则早就在，依旧犯了。再加一条同类自查，等于加更多已经失效的东西。

## 触发与 review 对象

**每个非平凡决策，在按它采取任何行动之前。** "行动"含写文件、起长跑、改远端状态、对外发话——**不以产出 artifact 为限**，无 artifact 的决策同样触发。**想没想清楚不是判据，行动线才是**："还在摇摆，先写个原型试试"不豁免，那个原型就是行动。对象是决策陈述本身，不是它将产生的 diff。

用户显式点名要审某个决策时同样触发，且**不走免审**：他点了名，平凡与否已由他否决。

**决策的单位是一个可陈述的选型或取舍**——能写成"在 A 与 B 之间选了 A"的那种。措辞、先读哪个文件这类拿不出可陈述备选的动作不构成决策，不触发本 gate。**别拿"命名"当例子**：给一个对外符号改名，备选恰恰陈述得出来（旧名 / 新名 / 第三个名），它落在下面的平凡判据里而不是这里。缺了这条下界，"非平凡"会退化成"一切"：任何动作都能被说成有替代方案，于是读者只能自设一条下界，而那条下界正是本 gate 要挡的东西。

**纯执行一个已过本 gate 的决策不触发**——它不是新决策，不需要任何声明。这与上面那条下界是同一类：两者都是"根本没到 gate 门口"，不是"到了门口被放行"。

到了门口之后，举证责任在"声明平凡"那一侧，不在"声明重要"那一侧。**下面两条须同时成立**才算平凡、可免审：

| 平凡判据 | 说明 |
|---|---|
| 只有一个可行做法 | 备选**陈述得出来**，但任何替代都严格更差，且理由一句话说得清 |
| 完全可逆，逆转成本近零 | 改回来不需要重跑、不需要重新取证、不作废已产出的数据、也不用向任何人收回已说出口的话 |

与下界的区别就在第一条的"陈述得出来"：**陈述不出备选 → 不是决策**（不触发，无声明）；**陈述得出但都严格更差 → 是决策、可免审**（要声明）。两者义务不同，别混。

免审的声明写在给用户的回复正文里，一句话说明这两条各自为何成立——不静默跳过，也不能只挑一条充数。**它必须先于那个行动发出**：动完再补一句就只是事后报告，拦不住任何事，而 gate 的全部作用就在拦。它不落盘：免审意味着没有决策记录要留，若这个决策值得落盘，它本身就不平凡。

**过了 `review-gate` 不抵本 gate，反之亦然**——两者都要过。那个审产物是否正确实现了决策，本 gate 审决策本身是否成立；决策错了的代码通常完全正确地实现了那个错误，因而能通过代码评审。这条在 user-scope CLAUDE.md 里也有一份：本 skill 的内容可能被复制进 subagent prompt，那条路径上 CLAUDE.md 不在场，故两侧各留一份，改动时同步。

## 喂什么

缺任一项即视为未喂齐，评审结论不成立：

| 输入 | 为什么不可省 |
|---|---|
| 决策陈述 | 一句话说清"决定做什么"，不是"要解决什么问题" |
| 被否决的备选 + 否决理由 | 缺它，评审者只能审"这个方案好不好"，审不了"它是不是比替代项好"——只与"不改"比是本 gate 要挡的头号失误 |
| 支撑证据及其取得方式 | 含"这个检查在结论为真/为假时输出是否不同" |
| 作用域声明 | 该决策的结论在什么范围内成立、超出范围会怎样 |
| 既有相关决策 | 交界面失效只有在两个决策同时在场时才看得见；单独审任一方都发现不了 |
| 已知未验证项 | 明确列出"要求过但没实测"的部分 |

以上六项是关于**决策**的事实。还有一半是**评审者自己的契约**——下面的判据表、返回格式与定级刻度、对抗式 framing，以及「不做」那三条方向约束，全都写在本文件里、**不在评审者的 context 里**。所以 prompt 必须把**本文件的绝对路径给它并要求它读**（被委派方有 `Read`，只是不自动继承）。不要在 prompt 里复述这些——复述一份就是第二真相，两份会各自漂移，而本文件是它们的单一 owner。

## 判据

判据 2–6 各出自一条真实失误；判据 1（只与"不改"比）来自同一轮里一次单独的自我修正，不在那五条之列；判据 7 补的是免审判据查、而评审此前不查的那一维。评审者逐条给结论，不得合并回答：

| # | 判据 | 失效形态 |
|---|---|---|
| 1 | 备选是否与**替代项**比过，而非只与"不改"比 | 单独审视每个选项会系统性偏向"什么都不改"，于是选中较重的一害 |
| 2 | 凡依赖"我们要求过"的地方，有没有**实测**它确实发生了 | 把写进规格/prompt 的要求当成已成立的事实 |
| 3 | 选作判据的量，在**本场景本题材**上有没有区分度 | 选了一个几乎是常数的指标当哨兵，回归发生时它也不动 |
| 4 | 这个选择在**没要求的维度**上还动了什么，动得均匀吗 | 工具为达成目标顺带改了别的东西，且对各对象影响不均，注入与能力无关的系统性偏差 |
| 5 | 与既有决策的**交界面**是否相容 | 两个各自合理的决策在交界处失效，任一方的单独审查都发现不了 |
| 6 | 结论的作用域是否**超出**证据的作用域 | 把只在某条件下成立的读数当成普遍结论用 |
| 7 | 这个决策**错了的话，多久能发现、改回来要付什么** | 不可逆或失败无症状的决策被按可逆的来对待——免审判据把可逆性当必要条件，评审却不查它，等于只在最便宜的那条路上把关 |

## 执行

| 项 | 取值 |
|---|---|
| transport | Claude Code：`CODEX_SANDBOX=read-only codeagent-wrapper --backend codex "<prompt>" <workdir> </dev/null`；Codex：内置 collaboration agent，按 `$subagent-spawning` |
| 档位 | `read-only`。语义与实测边界见 `~/.claude/references/delegation-policy.md`「Codex transport」的沙箱档位节，本节不复述。**prompt 里必须告诉评审者它自己禁网**——否则它会把随之而来的失败当成环境故障去排查，而不是当成"证据没喂齐"报回来；那个失败长什么样见上述档位节 |
| 等待 | 同步。gate 阻塞后续动作，真后台化只平添巡检负担 |
| framing | 对抗式：要求评审者优先证伪，而非确认 |

评审者对每条判据返回一行 `判据 | 结论 | 依据`。结论取 `成立 / 不成立 / 不适用 / 无法判断`——**每一种都要给依据**，包括「不适用」和「无法判断」，否则下表里那两行的核查义务没有对象。对「不成立」再定级：`blocker`（决策本身不成立）/ `应修`（决策成立、但有指名的弱点）/ `提示`（不影响成立与否）。三个非成立取值别混——**不适用**是该判据在本决策上没有对象（首次决策就没有"既有决策交界面"），**无法判断**是有对象但证据不足。

## gate 裁决

下表是这些取值的**唯一处置表**。终态出口只有 `放行 / 复核 / 交用户` 三种；`不阻塞` 不是终态，它是"这一项不影响出口"的标注，最终仍由第一行决定放不放行。本文件别处不再另列一份——四个面各写一份正是这份逻辑此前反复自相矛盾的原因。

| 评审者返回 | 怎么处置 | 出口 |
|---|---|---|
| 无 `blocker`、无 `应修`、**无「无法判断」**（全部成立/不适用，或只剩 `提示`） | — | **放行** |
| 某项 = 不适用 | 核一眼它真的没有对象：评审者拿它当"我不想查"的出口时，与真·不适用同形 | 不阻塞 |
| 某项 = 不成立 / `提示` | 随决策一并落进 adr 记录——否则这一级没有消费者 | 不阻塞 |
| 某项 = 不成立 / `应修` 或 `blocker`，且修正**不改变决定本身**（补证据、收窄作用域、补上漏掉的对照） | 直接修，回传原评审者**只答两问**（修正是否成立、有没有引入新问题），不重开全审；判不成立则回到修正 | **复核** |
| 某项 = 不成立 / `应修` 或 `blocker`，且修正**会改变决定本身**（换方案、放宽约束） | 那是一个新决策，而本 gate 不替用户做决策 | **交用户** → 用户选定后按新决策**重走一遍完整 gate**（不是两问复核：换了方案就没有原决策可对照） |
| 任一「不成立」项，用户选择**带着它原样落地** | 即 waive。理由与该项一并写进 adr 记录 —— 它与上一行的区别只有一个：不换方案，所以不重走 | **放行** |
| 某项 = 无法判断 | 补喂对应输入后复审该项；复审通过则该项取值改变、重跑本表 | 补不出 → **交用户**裁决：判阻塞 → 不放行；判接受 → **放行**，理由与该项一并写进 adr |
| 评审调用失败 / 超时 / 结果无法解析 | 视同 gate 未过——重试或重新发起；不得静默降级为自查 | 仍不行 → **交用户** |
| 多轮不收敛 | — | **交用户** |

**多行同时命中时按最重的出口走**：交用户 > 复核 > 放行。标着「不阻塞」的行从不单独决定终态。**「无法判断」未消解前不得放行**——它不计入通过，而"补喂后复审"不是终态出口、不参与上面这个排序，所以必须单说一句，否则它会被漏成放行。消解只有表里那一行给的两条（补喂后复审通过 / 用户裁决接受），处置也在那一行，本句不另立。

**复核轮怎么回传**：Claude Code 侧 `CODEX_SANDBOX=read-only codeagent-wrapper --backend codex resume <session_id> "<复核任务>" <workdir> </dev/null`，`<session_id>` 取首轮 wrapper 打印的 `SESSION_ID`、`<workdir>` 与首轮同值；Codex 侧按 `$subagent-spawning` 续用原 agent。**handle 取不到就不是复核**——按上表「评审调用失败 / 超时 / 结果无法解析」那一行处置，另起一个评审者并把首轮 finding 与修正一并喂进去，不得把新起的一轮当成续审报成"复核通过"。

## 输出

放行后，决策连同**其作用域与已知未验证项**一并落盘。载体按 `~/.claude/references/docs-organization-protocol.md` §4.4 定——`docs/adr/`，append-only、每条一文件、改变主意时用 supersession 而非原地改写；那份协议是单一权威，本节不另指定落点。作用域不落盘等于没有：后续读者会把它当无条件结论用，那正是判据 6 要挡的事。

## 不做

- 不审实现。产物是否正确实现了已过审的决策，归 `review-gate`。
- 不替用户做决策。评审者给的是"这个决定站不站得住"，最终决策人不变。
- 不因为决策"看起来很小"就免审——本 gate 的五条来源里，有两条当时都被判断为小改动。
