## 探索目标矩阵

此矩阵仅支持初步发现。发布目标矩阵仍需用户确认。下表是常见的浏览器游戏起点，按本游戏的支持承诺增删——
关键是每行都写明**它不能证明什么**，否则一次仿真通过会被当成真机通过。

| 发布目标 | 最低观察要求 | 不能证明什么 |
|---|---|---|
| iPhone 尺寸 Chromium 仿真 | 响应式布局、触摸尺寸控件、明显溢出 | Safari/WebKit、键盘、音频、安全区域或存储行为 |
| iOS 模拟器 WebKit | WebKit 布局、键盘、`dvh` 与安全区域预检 | 真机触摸、音频解锁、存储配额或前后台切换行为 |
| 真实 iPhone Safari | 用户确认的 `P0` 必过旅程，以及触摸、键盘、缩放、音频、刷新/存储和前后台切换 | 其他 iOS 版本或第三方 iOS 浏览器壳 |
| 普通笔记本视口下的桌面 Chrome | 指针/键盘交互和桌面框架 | 桌面 Safari/Firefox/Edge 兼容性 |
| 声称广泛支持 Apple 浏览器时的桌面 Safari | 共享 WebKit 行为和桌面布局 | Windows 浏览器家族 |

## 暂定核心旅程

以下旅程通过逆向理解得到，是候选而非真实产品优先级。请在意图门确认发布 P0 子集。
每条只写**用户可观察**的成功标准——写成内部状态或实现细节，测试代理就无法独立判定通过。

| 旅程 | 用户可观察的成功标准 |
|---|---|
| 首次启动与新手引导 | 游戏在没有无解释延迟的情况下进入可用状态；初始输入与进入主界面都正常 |
| 主界面导航 | 各主要入口一次响应，并提供易理解的返回/主页行为 |
| <核心玩法循环> | <玩家能完成该循环并看到即时反馈> |
| <进度 / 成长循环> | <操作按预期明显影响进度，并在后续互动中体现> |
| 持久化 | 刷新、手动保存/读取、稍后回流和新游戏按承诺保留/重置数据 |
| 设置与自定义 | 各项自定义有可见反馈，并在存储上限处安全失败 |
| 交付模式降级 | 缺少宿主/CDN/网络时，要么提供真实支持的降级路径，要么明确解释，不能一直卡住 |
