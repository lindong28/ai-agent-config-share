# reuse-for-aigc

## 术语

- **X** = 任务点名要复用的那个既有物（开源项目 / 别人的 skill / 一套成文方法）。
- **Z** = 你为跨过集成障碍而自建的中间物：垫片、桥、适配器、替代实现。

## 这个 command 为什么存在

「复用 X 产出 Y」有一条塌陷路径：撞上第一个集成障碍 → 建 Z 跨过它 → Z 继承主任务的全部严谨度预算 → Z 变成了任务。

**关键在于它绕过了哪道闸，而不是哪道闸不存在。** `decision-review` 的判据 1 是「备选是否与替代项比过，而非只与'不改'比」，它的输入表要求写下"被否决的备选 + 否决理由"——「建 Z」这个决策进了那道闸，就会被逼着写下"直接跑 X"及其否决理由，而那句否决理由往往正是一条从未被检验的反向断言。

它没被进入的方式是**措辞**：`沙箱调不了 CLI ⇒ 必须包成 HTTP`。必要性不长成「在 A 与 B 之间选了 A」的样子，于是落进 `decision-review` 自己写的下界之外（"陈述不出备选的动作不构成决策"）。

**垫片事故**（2026-08-23，本 harness，实测）：任务是挑一个开源视频项目做二次开发出片。撞上"它的沙箱调不了本地 CLI"后建了 HTTP 垫片——92 个测试、3 轮对抗评审、8/8 守卫变异，全绿。该 session **85% 的插入行（2,944 / 3,484；垫片本体 2,530、适配器 414）落在 Z 上**，而 X 直到最后半小时才第一次运行——它一条命令就能无头启动。全程 `decision-review` 零进入（transcript 实测 0 命中，阳性对照 `review-gate` 56 命中）。

## 骨架

| 节 | 角色 | 返回边 |
|---|---|---|
| §0 记名 | 前置 | 名字未定 → 出去收敛名单，回来选一个 |
| §1 拿到 baseline | **闸**：不过就地停 | 判"跑不起来"前先过反向断言 |
| §2 决定要不要建 Z | **决策点**：走 decision-review | 返回条件命中 → 回 §1 |
| §3 二次开发 | 阶段 | — |
| 停轮读数 | 每轮义务，不占流程位置 | 跳闸 → 交用户 |

## §0 记名

写下任务点名要复用的那个 X——项目名 / skill 名 / 方法出处。没有名字，下面那条判据无从谈起。

名字不止一个时，先按 `evidence-sufficiency.md`「发现候选的检索」把**品类内的名单跑完整**（注意那边的"收敛"指名单不再增长，通常会让名单变长），再从名单里选定一个写进本节。

## §1 先拿到 baseline，不改一行

在做任何集成工作之前，让 X 按它自己的方式产出一次它自己的产物。

判据是**拿到它的产物**。三样都不算：装好了、读懂了它的源码、跑通了它的测试——它们与"根本没跑过"在产物上完全一样。

| X 是 | baseline 是 |
|---|---|
| 一个项目 | 用它默认的配置跑出一件成品 |
| 别人的 skill | 原样调用一次，拿到它的输出 |
| 一套成文方法 | 照它原样走一遍，产出一件东西 |

这一步同时给出**参照上限**：X 自己能做到什么水平。没有它，后面任何改动都没有"改好了还是改坏了"这个读数。

跑不通就地停。**判"X 跑不起来"是一次反向断言**——先按 `evidence-sufficiency.md` 问一句：它其实跑得起来的话，我这套检查会给出不同读数吗？（垫片事故里答案是"不会"：只看了 GUI 那条入口，而它另有一个无头入口。）

## §2 决定要不要建 Z

**「要不要建 Z」是一个可陈述的 A/B 决策，先走 `decision-review`。** 别让它以"技术必要性"的措辞绕过去——`必须先 X 才能 Y` 与 `在 建Z / 换一个X / 放弃复用 之间选了建Z` 是同一件事的两种写法，只有后者进得了那道闸。

同时它是用户拥有的 choice（建 Z / 换一个 X / 放弃复用路线），按 `AskUserQuestion` 出，选项里带上下面那句返回条件的初稿。

决定建了，动手前先写一句：**Z 做到什么程度，我就回去跑 X。** 写不出说明 Z 的终点没定义，而没有终点的手段会长成目的。返回条件命中即停 Z、回 §1 重跑 baseline；下面读数 1 就是它每轮的检查点。

两条推论：

- **Z 的投入上限由 X 是否跑通决定。** X 还没产出过东西时，Z 只做到"能让 X 跑起来"。该过的闸照过——Z 此刻通常落在 `review-gate` 的 trivial 免审档里，但算不算 trivial 用那个 skill 的判据，别在这里另立一套。在一个还没被验证值得用的东西上做加固，是把预算花在一个可能整个作废的分支上。
- **Z 自带的质量闸不构成停在 Z 上的理由。** 自研分支会长出它自己的设计评审、blocker、验收缺口，而它们的存在会让"停在 Z 上"显得正当。判据是那些 blocker 是否只因为你在自建 Z 而存在——是，就说明 X 那边可能本来就没有这个问题（垫片事故：8 个 blocker 里 5 个属此，而 X 自带一个可用的同类机制）。

## §3 二次开发只在 baseline 之上做

每一处改动对着基线问：这一处比 X 自己做得好在哪，读数是什么。

改动引入新的合成 / 接合 / 多步生成机制时，那部分照常走 `/custom:create-aigc-design`——只对你新增的那部分，不对 X 原有的机制重建一套。

判定"X 真的不合用、要换"时，回 §0 换一个 X 重走全程；判定该品类整体不可复用时，本 command 结束、转自研。两者都按 §2 那次提问交用户定。

## 每次停轮报两个数

| 读数 | 怎么写 |
|---|---|
| X 自己产出过东西没有 | 是 / 否 + 产物是什么。否 → 卡在哪一层、下一步怎么解 |
| X 侧 vs Z 侧的产出占比（仅当 Z 存在时报） | 口径固定用**改动行数**（git 可核，垫片事故里唯一被证明会变的那个）；Z 不是代码时用耗时。同一任务内不换口径。Z 不存在时写"无 Z" |

**跳闸条件**：「X = 否」且 Z 侧占比 > 50% 连续两轮时，停下来把这两个数和"要不要继续这条路"按 `AskUserQuestion` 交用户——此时的判断依赖他持有的事实（这个 X 值不值得继续），不是你能替他做完的活。

没有跳闸条件时，读数 1 在塌陷全程恒为"否"，而每一轮都答得出"卡在哪、下一步怎么解"——那是一盏一直亮着、不触发任何东西的灯。

## 反模式

| 反模式 | 为什么坏 |
|---|---|
| 因为"X 的默认画风 / 配置不合用"就改成自研 | 先跑 baseline 拿到它的产物，再判断是调 X 的参数还是真要换。没有 baseline 时这个判断做不了 |
| 把"我给 X 写了适配器并测通了"报成"用上了 X" | 桥能走不证明有人从桥上过去。这是读数 1 被伪造的具体形态 |
