# review-aigc-design

对 AIGC 设计文档做独立评审，只在**算法-视觉-效果层**挑刺（是否产生断层/鬼影/孔洞/残渣/可见重复/漂移），在设计层拦下问题。

主 session 先完整读 `~/.claude/references/aigc-design-review.md`（核心视角、五条硬纪律、接合类型学、7 维评审 rubric、缺陷判据、评审平面边界）。

**触发重评审**：若设计的**流水线机制已实质变更**（换了另一套生成/合成/编辑路径，非同一机制的参数调整），旧评审作废，须对**新机制**重跑本 gate（硬纪律 3）。评审平面只覆盖**算法层**失败模式；**风格保真**（匹配 exemplar 的量化风格判据）需独立 style-judge gate、不在本命令职责内。

## 工作流

1. **并行起独立评审 subagent（默认 2，可更多）**（general-purpose），各带底座 + 设计文档路径 + **可实测真实素材/地标集路径** + 不同侧重（典型 2 路：A=接合算法/分布独立性/周期性；B=分类器可分性/假设普适性/conditioning/验证充分性；多于 2 则按维度均分、合起来覆盖 7 维全维、无遗漏无重叠）。subagent 相互隔离、各自独立调研，不复用主 session 结论。
2. 每个 subagent 的 BINDING 指令：
   - 逐维按 rubric 审；**逐真实输入/地标**推演，不泛泛。
   - **五条硬纪律照底座执行，尤其"能实测优先实测"**——把设计里的候选算法/阈值跑在给定真实素材上看结果，而非头脑推演；验收失败模式用量化探针、探针须对准该失败模式真实形态（硬纪律 4）。
   - 逐条审 L3 的每个"达成/规避"论证：是否存在某输入使它悄悄失效、重新触发某必避问题？作者自列的开放风险是否完整、缓解是否真解决还是又一个补丁？
   - 输出按底座缺陷判据分级，结尾直答**能否进入实现 + 必须先修哪几个 blocker**。
3. **主 session 综合**两份评审：合并同根缺陷、按严重度排序、给出收敛裁决。
4. **gate**：有 blocker → 不可进入实现。与作者迭代修设计（真取舍用 AskUserQuestion 让用户拍），修订后对**改动部分**重审，直到无 blocker 才放行。

## 输出

一份综合评审：blocker/major/minor 分级缺陷清单 + 收敛根因 + 明确裁决（现在能否按此设计进入实现）。**QA 数字/agent 目视不作放行依据**——验收锚定目标失败模式（如 1:1 人眼）。
