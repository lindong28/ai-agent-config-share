# create-delivery-report

把一次已完成的交付，写成一份**给读者自己判断要不要用、怎么用**的单文件 HTML 报告。

## 何时使用

| 用 | 不用 |
|---|---|
| 一段工作已交付，要交给**没参与的人**（同事、下游团队、评审方）判断和上手 | 交给另一个 agent context 接力实施 → `/custom:create-plan` |
| 产物是网站 / repo / skill / artifact / 一套流程，读者要据此决定用不用、怎么用 | 只是汇报进度或答疑，无人需要照着上手 |
| 用户说"写个交付报告 / 给同事看的说明 / delivery report" | 单个 artifact 的使用说明 → README |

## 输入

命令本身不调研。开写之前**必须已经掌握**下列事实；缺哪一条就先去取，取不到就在报告里标为未核实——不要用推断填。

| 必需 | 取法 |
|---|---|
| 每个产物的**当前**可达地址与状态 | 亲自访问一次。仓库用 `git fetch` 后比对 `HEAD` 与 `@{u}`，**不看 `git status` 的 ahead 计数**——它相对上次 fetch，多 session 并发时会系统性地骗你 |
| 读者要在**自己的工作流里**多做哪一步 | 从读者的起点推，不是从你的实现推 |
| Quickstart 的每一步真的能跑通 | 逐条实跑，含耗时。没跑过的步骤不写进 Quickstart |
| 已知问题与边界 | **三个来源都要走，按成本从低到高**：**① 缺陷账本**——`docs/issues.md` 一类持续记录的档，没有就翻 issue tracker 与近期 commit，不靠回忆；**② 你正在汇总的那几份 unit / phase 报告自己的「遗留风险 / 未验证边界 / 未做」段**，逐份扫，别只扫台账；**③ 输入面数据流追踪**——交付物声明接收的每个输入，逐个回答「它到不到得了产出」，中途被丢弃 / 恒为默认值 / 从未被读取的写进 §6 并给行号，**「到得了」也要给出最终产出调用的那一行**（否则那句不可证伪，而它占绝大多数）。为什么三个都要、以及交付物没有输入面时 ③ 怎么走，见表下 |
| Block 在读者那边的事 | 写清"为什么非他不可"，否则读者会当成可选项 |
| **凡要写进报告的具名指标 / 配置项 / 字段，先取到它的权威语义读数** | 逐个记「符号 → 权威载体路径 → 你从那里读到的定义原文」。**名字读起来像什么不算证据**：实测一次交付把 `identity_continuity_cosine` 写成"当前帧与**参考图**的相似度"，而权威定义是与**该片自己开头 0–10 秒确认的稳定脸**比、并明写"起始窗本身就认错人时这个数仍可能很高"——错的那版更符合直觉，所以既没触发怀疑、也没被自查拦住，是交付前 review 才抓到的。取不到权威原文就标"未核实"，**不许按名字补语义**：这类句子读者会直接拿去用，教错了比留白贵得多 |

**「已知边界」为什么要三个来源。** 账本只装**缺陷**，装不下**被有意作用域化的能力边界**——那类东西不是 bug，没人会给它开 issue。但它通常也**不是只活在代码里：上一手往往写下来过**。实测一次交付：服务把首帧图 sha256 后即丢弃，报告的「已知边界」认真填了六条、偏偏没有这一条；而建这个服务的那份 unit 报告，在一个叫**「遗留风险与未验证边界」**的小节里第一条就写着「当前 writer 看不到首帧像素……这仍是语义质量缺口」。**没人把它搬过来而已。** 所以 ② 比 ③ 便宜一到两个数量级，排在它前面——而那次事故的复盘（连同该项目自己记的教训）只查了 plan / state / journal 三份台账，同样漏掉了 unit 报告这一层。

③ 兜的是**真没人写下来**的那一半，判据是数据流不是词表：上例里「sha256 之后丢弃」这一步在代码里没有任何标记词，grep 不到；而带标记的那半（`pixels_available_to_current_writer: False`）其实 grep 得到。所以别把 ③ 读成"不许用 grep"——grep 抓得到有标记的，抓不到无标记的，后者只有顺着数据流走才看得见。

**交付物没有声明输入面时**（一份报告、一批数据产物、一套流程），③ 换一个起点：**报告里每一句「它会用到 / 支持 / 覆盖 X」的宣称**，逐句回到实现问一次它撑不撑得住。这样成本被宣称数（个位数）钉住，而不是被输入面钉住；上例里 header 那句「首帧被完全参考」正是这样一句撑不住的宣称。

## 结构

**顺序即优先级。** 读者的注意力在开头最高、往下递减，所以最贵的信息放最前，越往后越可折叠。

| # | 章节 | 回答什么 | 展开态 |
|---|---|---|---|
| 0 | 摘要卡 | 30 秒版：交付了什么、现在能不能用、要我做什么 | 常驻，不可折叠 |
| 1 | 解决什么问题 | **从读者的场景写**，不是从系统能力写 | 常驻 |
| 2 | 交付物清单 | 每个产物一行：是什么、在哪、什么状态、多大规模 | 常驻表格，见下 |
| 3 | 怎么用 | 设定一个具体用户场景，走完整条路 | 常驻 |
| 4 | Quickstart | 最短可验证路径 + 每步预期看到什么 | 常驻 |
| 5 | 人工协议 | 不说就会出事的约定 | 常驻，视觉上要显眼 |
| 6 | 边界与预期 | 不支持什么、要等多久、什么还没验过 | 常驻 |
| 7 | Block 在你那边 | 逐条写为什么非他不可、大概多久 | 常驻 |
| 8 | 参考 | 深链、commit、账本条目 | 可折叠 |

某一节本次确实没有内容时，**保留标题并写明为什么空**（统一写成"本次无 X"，如"本次无人工协议"、"本次无已知边界"——两处用词不同会让读者以为是两种情况），不要静默删节——读者看到 1–3–4 会以为自己漏了一段，而"没有"本身是信息。

**摘要卡里必须有一句"现在能不能用"的直接回答**，不是"取决于……"。

### 交付物清单要覆盖四类，别只列"能点开的东西"

按访问入口组织清单，是这一节最常见的失效：网站、仓库、目录各占一行，而**真正被生产出来的东西**（数据集、规格、仪器）降级成了折叠区里的背景说明。入口是通向产物的路，不是产物本身。

| 类 | 是什么 | 漏掉时读者失去什么 |
|---|---|---|
| **入口** | 网站、页面、路由、CLI 命令 | — 这一类没人会漏 |
| **资产** | 生产出来的数据：输入集、生成物、语料、标注、跑出来的读数 | 看不出这次到底产出了多少东西，也不知道能不能拿去复用 |
| **仪器与规格** | 定义与实现：指标定义、评分器、验收 gate、流水线、归一化规格 | 以为只拿到一批数，其实拿到的是一套可以重跑的装置 |
| **知识** | 证据文档、缺陷账本、沉淀的教训 | 引用数字时不知道边界在哪 |

判据一句话：**如果有人要在另一个项目上复用这次的工作，他要拿走什么？拿走的每一样都是交付物。**

资产与仪器**必须带规模数**（多少条、多少维、多少行、覆盖率），且规模数要能与 §4 的验证对上。没有数量的资产读起来像一句形容词。

**"在哪"要让读者点得进去，而不是一个路径字符串。** `metrics/out/` 说不清是哪个仓哪个分支，也点不开。代码给 forge 的 blob / tree 链接，**ref 用 commit 或 tag，不要用会漂的默认分支**——指向 `main` 的链接在报告发出三周后会指到别的内容，而且照样返回 200，读者无从察觉。存储系统上的产物给 URL，没有 URL 的给 URI（前提是读者取得到，见下段）。（怎么验见 §交付前自验。）

**读者打不开的东西不写进报告**——私有仓、个人知识库、只有你有权限的存储，列出来读者只会点到 404。**改为在对话里告诉用户**：改了哪些、内容是什么、是否值得迁到读者可见的地方。迁不迁由用户定，不由报告替他公开。

因此**核实与呈现是两件事**：改动落在几个仓就核几个（凭印象会漏，也会把没改的算进来），但清单里只留读者可达的。

**中间产物同样是交付物。** 为了产出最终结果而造的输入集、首帧图、prompt 集合、验收脚本——它们下一轮还要用，而且往往比最终结果更耐用。「它只是个中间步骤」不是省略的理由，是它属于"资产"还是"仪器"的判断问题。

**每一节内部再分主次**：常读的写在节的正文，深细节收进 `<details>`。折叠的默认收起，摘要行要能独立读懂——读者不展开也知道里面是什么。

## 写作

沿用 `~/.claude/references/human-facing-message-principles.md`（通道无关，适用于此）。**不要挂 `cli-output-review-principles.md`**——它自述不适用于「GUI；一般文档」，其判据在 HTML 报告上没有指称对象。

本节只补这个通道特有的：

- **状态用徽章表达，不用形容词。** 每个产物、每条边界都带一个状态：可用 / 部分可用 / 待验证 / 不可用。"基本完成"这类词不构成状态。
- **数字带作用域。** 「准确率 0.83」要写清在什么池子上、n 多少。读者会拿它去别处引用。
- **不许有"详见代码"**。要么在报告里说清，要么给可点击的深链。
- **失败也要写进去**。一份只有成功的交付报告，读者会怀疑其余部分。
- 语种随读者，与 agent 对用户说话的语种无关。

## 页面

单文件、无外部依赖——离线可开、可当附件发。

**视觉参数取 `web-visual-system` 的 `references/reading-instance.md`**——长文档档位，单列长读。不要在这里另发明取值（数值只在那一份里，抄过来就会各自漂移），也不要退回它的 console 实例：那份是 11-13px 的密集界面档，读一页正文很累。

上面那句「单文件、离线可开」会激活该实例里若干只在 `file://` 下成立的约束——按它办，不在这里复述机制。

## 交付前自验

写完不等于能用。逐条跑，一条不过就不交：

| 检查 | 判据 |
|---|---|
| **当读者用一遍** | 两半。**读**：取渲染后的 `innerText`（展开全部 `<details>`）从头读到尾，不看源码——找的是源码检查找不到的东西：前后矛盾的数字、读不懂的简称、承诺了却没兑现的链接、以及"这一段到底想让我做什么"。扫源码、数元素、跑正则替代不了它，**但它们跑起来很像在验收**。**用**：交付物有可点的东西时，各报一次从点下去到画面更新的秒数（量法见 `web-ui-observation.md`「测量技术」，含它要求的阴性对照）；没有可点元素的写 `n/a(静态页)` 并补一个首屏可读时刻的读数 |
| 在浏览器里真的打开一次 | 锚点跳转、折叠展开、代码复制逐个点过 |
| 窄屏 375px | `document.body.scrollWidth <= window.innerWidth`；溢出时列出实际越界的元素，而不是只报一个布尔 |
| 正文占比 | 宽屏下 **`<main>` 那一列的宽度** ÷ 视口 ≥ 70%。量的是内容列，不是文本行长——行长被 74ch 限着，拿它去除永远不达标 |
| 真的无外部依赖 | 断网或屏蔽外部请求后再开一次：字体、脚本、样式、图片全部内联或内嵌，**只有正文里的超链接可以指向外部**。少一条内联，读者在会议室 wifi 上看到的就是另一份文档 |
| 无裸路径 | 全页扫 `<code>`：**含 `/` 且不在 `<a>` 内**的应为零（`pre` 里的命令除外）。别把判据写成某个仓的顶层目录名清单——换个仓它就恒返回 0。斜杠不构成路径的（`N/A`、`16px/26px`）逐个排除并**把排除项列出来**：排除要留痕，否则等于悄悄放宽判据 |
| 每个外链可达 | 逐个请求，记状态码。302 到登录页正常。**404 分两种，处置相反**：链接本身错了（ref 没推、路径拼错）→ 修链接，别删行；这个交付物读者本来就够不着（私有仓、个人库）→ 整行下架，在对话里交代 |
| 代码链接的 path 真的存在 | **状态码证明不了这个**——需要登录的 GitLab 对任何路径都回 302，含根本不存在的。先 `git ls-remote --exit-code origin <链接里的 ref>` 确认那个 ref 在远端存在，再 `git ls-tree -r --name-only <该 ref>` 比对 path。**不要用本地 `HEAD`**：本地已提交未推时它与读者看到的树不是同一棵。尤其当心被 `.gitignore` 排除的目录（媒体、数据、产物）：本地明明有，仓里一个文件都没有 |
| Quickstart 逐步实跑 | 含耗时。写"约 2 分钟"就要真的计过 |
| 报告里每个数字有出处 | 抽查三个，回到原始产物核对 |
| 每条边界有来源 | 两半，**来源写在自验输出里、不写进报告**（账本条目号对外部读者既打不开也无意义）。**可注入的一半**：每条边界配一个来源 token（账本条目号 / unit 报告路径+行号 / 代码行号），**无来源的条数应为 0**——删掉某条的来源看它变不变红，与「无裸路径」同形。**判断的一半**：三个来源各自的产出各写一句——账本查了哪几条、unit 报告扫了哪几份、数据流追踪的**输入清单出处与项数**（schema 路径 / 签名 / `--help` 的哪一段，`N = ?`）再给 N 行结论。项数由你自己定时，1 行与 40 行输出相同；只报"边界写全了"在真写全与漏掉一整类两种情况下同样相同，而漏掉的那一类恰恰是账本里没有的那一类 |
| 清单覆盖四类 | 逐类写一句它在这次交付里对应什么。本次确实没有的写「无」+ 依据；**有、但读者不可达的写「N 项，读者不可达，已在对话中交代」**——不可达不等于这一类从清单上消失 |

判「看起来对不对」时按 `~/.claude/references/web-ui-observation.md` 观察——上表大多是**值层**检查（宽度、对比度、计数），而该档规定的覆盖面比值层宽得多。上表的「当读者用一遍」那一行就是该档「交付前的最低证据」第一条在本命令里的实例：**两处是同一条要求，不是两条**，判据与范围以该档为准。

**上表每一行只写了通过方向，所以每一行都要另有一个"它会失败"的证据。** 两类行的做法不同：

- **有数值或状态码输出的**（375px / 正文占比 / 无裸路径 / 外链可达 / path 存在 / **用一遍的「用」那一半** / **边界来源的「无来源条数为 0」那一半**）：把缺陷临时造回去——塞一条裸路径、把容器改成 1100px 居中、指一个仓里不存在的 path——看该行是否变红。变不红就说明它在两种情形下输出相同。
- **判断类的**（用一遍的**读**那一半 / Quickstart 实跑 / 数字有出处 / **边界来源的「三个来源各自产出」那一半**）：没有可注入的缺陷，等价要求是**写出观察到了什么**——矛盾与读不懂之处的清单（可以为空，但要写出来）、每步实际耗时、抽查的那三个数各自的出处。只报"跑过了"同样在两种情形下输出相同。
- **用一遍的「用」那一半属上一类、不属这一类，而且两样都要**：**阴性对照**（做一个不该改变任何东西的操作，看仪器报不报得出"无变化"）证明仪器分得清"变了"与"没变"——它抓得住恒定 16 ms 那个假读数；但它**不证明仪器量得准**：一个在第一次 mutation 就停表、把 1.5 s 报成 0.2 s 的仪器照样全过。对应上一类"看该行是否变红"的是**阳性注入**——临时塞一段已知延时，或开 CPU / 网络 throttle，看秒数是否跟着动。两样都做过才算这一行有失败证据。

这不是新规矩，是 CLAUDE.md「取证的充分性」在本命令上的实例；写在这里是因为**上表看起来已经很像证据了**，最容易在这里放过自己。（实测：本命令的头两次自验就用无区分度的检查把空页面报成完整。）

## 交付路径

报告本身也要能被读者打开。按读者的可达性选，并**实际验证一次**：

| 读者 | 路径 |
|---|---|
| 已有内部站点且读者能登 | 挂到那个站点的路由下，与产物同一入口 |
| 无站点 | 起本地 server，**统一交付、不按拓扑分派**——见 `~/.claude/references/remote-web-delivery.md`：一律交同一份（链接 + 转发前置 + 退路 + 停止 + 边界 + 回执状态），唯一分支是本机有无 sshd |
| 只是要一份能发的东西 | 直接发那个单文件 |

**不要走 `publish-demo`**：它是发到公网的，其 description 明文排除 colleague access。内部交付报告推上公网既超出本命令的范围，也会把内部深链一并公开。用户明确要公开发布是另一件事，由他直接调那个 skill。

## 反模式

只列前文规则**推不出来**的失效形态：

- **按实现顺序组织**——读者不关心你先做了什么，关心他要做什么。规则层看不出这条，因为按时间叙述的每一段单独看都成立。
- **Quickstart 从安装环境开始**——那是给开发者的起点；读者的起点是他已有的工作流。
- **"已知问题"只写不影响使用的小事**——真问题藏起来，读者第一次踩到就不再信这份报告。
