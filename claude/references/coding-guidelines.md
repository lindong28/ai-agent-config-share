# Coding Guidelines

修改或重构代码时遵循本文件。目标是用最小、可验证的改动满足需求，同时保护用户已有工作。

跑取证命令前另读 `~/.claude/references/evidence-sufficiency.md`——阳性 / 阴性对照、证据取自什么环境、取证命令对凭据的回显、以及不让失败与成功同形。那几条不限于编码相位，故不住在本文件。

## Think Before Coding

- 明确假设。
- 存在会改变产物或取舍的多种解释时，按 user-scope `Surface Choices (Real Ones), Recommend One` policy 对齐；能由当前 scope 和事实自行判断的实现细节不转嫁给用户。
- 有更简单的实现时说明理由；不清楚时先定位缺失事实。

## Simplicity First

- 不实现需求之外的功能。
- 不为单一 use case 增加抽象、灵活性或配置层。
- 不为不可能发生的情况增加错误处理。
- 如果实现明显大于问题本身，先缩小设计。

## Concurrent Batch I/O

迭代独立、I/O-bound 且规模不可忽略的工作项时，默认使用有界并发。

- 逻辑独立不等于资源独立：会争用同一磁盘、数据库、端口、外部配额等瓶颈，或把 wall-clock timeout 当成正确性信号的任务，须按共享资源容量定并发；并发会污染结果时，有界并发上限可以是 1。
- 只有存在顺序依赖、共享瓶颈、计时敏感、调试需要等具体理由时才串行；rate limit 通常意味着降低并发上限，而不是退化为串行。
- 不适用于 CPU-bound 循环、共享可变状态，或不在本次需求范围内的既有串行代码。

## Surgical Changes

- 只修改能追溯到用户需求的内容。
- 保留无关的 dirty worktree 内容；不顺手清理、重排或格式化相邻代码。
- 匹配现有风格。
- 清理由本次改动制造的 unused imports、variables、functions 或 orphan files；不删除既有 dead code，除非用户要求。
- 编辑手段本身不能让"没改成"与"改好了"同形。静默 no-op 的替换（字符串不匹配即无操作、锚点找不到即跳过）不会报错，于是你会如实相信并对外报告已修复，而文件一个字节没变——危害是**报告失实**，比改动失败更难发现。用不匹配即报错的手段，或写入后按改动的可观察特征复核。同一处被反复指出未修复时，先验证写入是否落地，再怀疑设计。

## Shell Authoring

- **Bash 里，变量后面紧跟非 ASCII 字符时一律写 `${VAR}`。** Bash 把全角标点吞进变量名：`echo "…$OUT）"` 求的是 `$OUT）` 而不是 `$OUT`，`set -u` 下当场 `unbound variable` 退出。**这是 shell 相关的**——同一段在 zsh 下正常输出（实测：bash 报 `OUT…: unbound variable`，zsh 打印 `value）`），所以别把它当成"shell 都这样"，也别因为在交互 zsh 里试过就以为脚本安全——**看你正在编辑那个脚本的 shebang**（本仓受跟踪的可执行脚本实测 68 个 bash、5 个 `#!/bin/sh`，两种都在）。**已因此挂过两次**（`$OLD_PID）`、`$OUT）`），两次都是跑到后段才炸、前面的副作用已经落地。
- **语法检查看不见它**：`bash -n` 与 `zsh -n` 都返回 0，失败只在运行期出现。所以判据不是"这个脚本有没有中文"，而是**有没有"未加花括号的变量紧邻非 ASCII"这条路径**；有的话给它留一个在 `set -u` 下真正**执行**过的最小样例。

## Goal-Driven Verification

- 把任务转成可观察的成功标准。
- 新行为或 bugfix 先建立失败证据，再实现并复验。
- 断言表达意图中该成立的**关系**（相对参照、集合性质、由约束推出的区间），不锁定本次观测到的巧合值。这种断言同样先失败后通过，却把错值、环境偶然值或第三方内容钉成契约，成因一变即假失败。确需字面值（含 golden/snapshot）时，注明来源与失效条件。
- 重构在改动前后验证相同外部行为。
- 多步实现使用最小必要的任务计划，每步绑定对应验证。
