# Concurrent Plan Isolation

多个 agent session 可能并发在同一 repo 上执行 plan（create-plan / execute-plan）时，避免彼此的改动、测试、运行时状态互相污染。单 session 独占 repo 时不适用。

## 核心：结构性隔离 ≫ 冲突检测

"互相检测再避让"是弱机制——要持续互看、临场协调，谁忘了看就撞。**结构上不共享可变状态**，撞车就不可能发生；检测只用于 merge 前发现文件面重叠。

流程骨架：**开工前**就位（三层隔离默认全上 · 登记占用 · 检测文件面重叠）→ 执行 → **完工清理**。

## 三层结构隔离（默认全上，不靠检测触发）

隔离恒常施加——不因"没检测到别的 session"就跳过；那正是要消灭的弱机制，且会踩穿下面的铁律。

| 层 | 隔离手段 | 铁律 |
|---|---|---|
| 代码 | 各自独立 git worktree | execute-plan 默认在独立 worktree 落地；plan 显式声明"单 session 独占"才免 |
| 可变运行时状态（生产 DB、数据文件、缓存、状态文件） | 开发/测试指向独立副本（`.backup`/`cp`，环境变量如 `*_DB` 指向副本） | 绝不在开发/测试中读写共享的生产实例 |
| 服务 / 端口 / 进程 | 起隔离实例 + 独立寻址（端口 / socket / 队列名 / 资源命名空间），不复用共享服务的寻址 | 绝不碰线上 / 共享服务 / 默认端口 / 生产部署目标 |

副本不回 merge：数据 / schema 的最终变更通过代码 + migration merge 回 main、由部署对生产实例应用一次；副本只服务本地开发测试，用完即弃。

## 外部不可复制资源（协调型，非结构隔离）

共享 LLM API 配额、限流、单点账号等**无法各自复制**的资源，不能结构隔离，只能**协调**——登记占用 + 串行化，或分账号 / 分配额；绝不让并发测试耗尽对方所需的配额。这是上面三层"复制型默认全上"覆盖不到的一类，需显式协调。

## 轻量登记（只补最后一环：文件面重叠）

结构隔离挡住运行时冲突后，剩下唯一冲突是"两条线改了同一源文件、merge 回 main 撞"。用一个 repo 内 git-tracked 的共享登记（约定位置，如 `.claude/active-work.md`）补上：

- 开工前：追加一条——worktree 名、占用的运行时资源、大致改动的文件 / 目录面。
- 开工前先读它：与既有条目的文件面重叠 → 协调（分工、排序，或约定谁先 merge）。
- 完工：删除自己的条目。

强度=约定（agent 开工读、完工清）；hook 强制留二期——结构隔离已挡住绝大部分，登记只补文件面重叠这一小片。

## 开工前检测（execute-plan 起步时）

1. `git worktree list` —— 有无其它活跃 worktree。
2. 读共享登记 —— 其它 session 声明的资源 / 文件面。
3. 三层隔离照常全上（与检测结果无关）。检测的唯一用途是发现**文件面重叠** → 按「轻量登记」节协调 merge。

## 与产品侧 singleton 规则的边界

本 protocol 管 agent 执行 plan 的工作流隔离。产品代码里 singleton / 服务在多 checkout 下的 ownership 自保护（per-machine/fleet 声明、detect another clone、拒绝 unsafe overwrite）是产品运行时规则，由项目侧的 CLAUDE.md / 代码承载、本 protocol 不复刻。

## 完工清理

merge / 交付后按三层隔离与登记各自的完工步骤统一清理（worktree、副本、隔离实例、登记条目），避免 orphan。
