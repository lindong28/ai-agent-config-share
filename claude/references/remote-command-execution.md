# 非交互 Shell 里执行命令

`ssh host '<cmd>'`、cron、launchd/systemd 作业、git hook 拿到的都是**非交互** shell。判据是这个 shell 交不交互，不是命令在哪台机器上跑；`-t` / `-it` 这类"给个 tty"的开关**不改变**它——带 `-c` 跑一条命令就是非交互，`ssh -t host '<cmd>'`、`docker exec -it ctr bash -c '<cmd>'` 都一样。

用户的环境几乎都装在 rc 里「非交互立即 return」那道守卫**之后**：`SSH_AUTH_SOCK`、PATH 段、shell 函数与 wrapper、代理变量、语言与工具链 env。

## 守卫在哪，决定了修法在哪

sshd 起的非交互 bash **会读 `~/.bashrc`**（`man bash` 有这条特例），只是读到守卫就 return——所以：

- `ssh host 'source ~/.bashrc && <cmd>'` **救不了**：它照样在守卫处返回。（实测：source 后 `SSH_AUTH_SOCK` 仍为空。）
- 但**守卫之前**的内容照常生效。所以某台主机若长期需要非交互也带上某些环境，持久修法是把那几行放到守卫**之前**（zsh 则放 `.zshenv`——它无条件读，交互与否都读）。这比每个调用点都记得加 `-i` 稳，也不会有下面那些噪声。

## 一次性调用怎么发起

| 场景 | 怎么写 |
|---|---|
| 简单命令，要 rc 环境 | `ssh host 'bash -ic "<cmd>"'`（远端是 zsh 就 `zsh -ic`） |
| 命令含引号 / `$` / 反引号，或输出要被程序解析 | `bash -s` + heredoc，见下 |
| 明确只依赖某几个变量 | `ssh host 'VAR=值 <cmd>'` |

**要 rc 就加 `-i`，并且别再加 `-l`。** 两个 shell 都只在交互时读 rc，但 `-l` 的后果不同：bash 的 `-lic` 走 profile 链、**不读** `.bashrc`（它能否间接读到，取决于被选中的那个 profile 里有没有回源钩子——发行版、安装器、用户手写都可能有或没有，实测四种布局结论不一致）；zsh 的 `-lic` 则照读 `.zshrc`。加 `-l` 对拿 rc 没有帮助，在 bash 上还会把它弄丢。

`bash -ic` 的两个代价：引号每多一层就要逐层转义（能写，但很快就不划算）；以及 **rc 里任何写 stdout 的东西（banner、`fastfetch`、提示语）都会混进你要的数据**——stderr 上那两句反而无害（`cannot set terminal process group ... Inappropriate ioctl for device` 与 `no job control`——前者措辞唬人，但它只是在说没有 tty）。命令复杂、或输出要喂给解析器时，改用非交互的 `bash -s` 从 stdin 收命令，需要什么变量就在开头显式给：

```sh
ssh host 'bash -s' <<'EOF'
export SSH_AUTH_SOCK="$(先在交互 shell 里读出真实值再填这里)"
<cmd 原样写，引号与 $ 都不用转义>
EOF
```

两处必须注意：占位符若原样留着，会**静默**把一个本来正确的变量覆盖成字面量（症状恰好又是 `Permission denied (publickey)`，绕回本文开头那个陷阱）；块里任何会读 stdin 的命令（`cat`、`read`、`ssh`、`ffmpeg -i -` …）都要显式 `< /dev/null`，否则它把剩下的脚本当输入吃掉，后续几行不执行而**退出码仍是 0**。

## 它把失败伪装成别的东西

缺失的环境从不报「环境缺失」，它报一个**看起来无关、且指向昂贵错误处置**的原因：

| 你看到的 | 真因常常是 | 会被误导去做的事 |
|---|---|---|
| `Permission denied (publickey)` | 没有 `SSH_AUTH_SOCK`，agent 里的 key 够不着 | 去给账号加一把**本来就在**的 key |
| `command not found` | rc 才加的 PATH 段没生效 | 去装一个**已经装好**的东西 |
| 连不上 / 超时 / 代理报错 | rc 才注入的 proxy 变量不在 | 去查一个没坏的网络 |
| 认证 / 授权被拒 | 凭据由 rc 或 agent 提供 | 去轮换凭据、改服务端授权 |

判据：**同一条命令加上 `-i` 再跑一次**，比较你关心的那个量（不是整段输出——banner、时间戳本身就会让输出不同）。两次不同 → 环境差异，不是凭据、不是网络、不是没装。

## 判据给不出答案时，如实报未核实

- **两次相同**只说明这次比对没能区分，不等于排除了环境。常见成因：远端登录 shell 是 zsh 而你比的是 bash（macOS 默认 zsh，此时该比 `zsh -ic`）；变量来自客户端 `ForwardAgent` / `ssh -A`，两种写法一视同仁；或它恰好设在守卫**之前**（那里本来就不缺）。
- **cron / launchd 根本无从比对**：你手动重跑的那次已经不在它们的环境里了，对照的外部效度不成立——别拿手工重跑冒充那个环境。

## 什么时候必须先做这次比对

在把上表任何一类原因**当成结论、或据其动手**之前。它们全是反向断言（「这台机器的 key 没被授权」「这台机器没装 X」），一旦说出口就删掉了后续检查的对象，而用户照它去操作的代价是真实的：加一把已存在的 key、装一个已存在的包、排查一个没坏的网络。

用户说「我自己 ssh 上去手动跑是成功的」时，这几乎就是本条——先比对环境，别去找第三种解释。

## 误判已经发出去之后

要明确说「上一条结论是错的，以这条为准」，而不是补一句「另外还有一个因素」——后者会让两个互斥的结论同时留在用户手里，而他并不知道该按哪个行动。
