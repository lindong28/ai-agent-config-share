# Evidence Sufficiency

`CLAUDE.md`「取证的充分性」落到操作层的做法。

**什么时候读**：读的时点由 `CLAUDE.md`「取证的充分性」单一持有——它绑在**事实主张外发之前**（外发面的清单见该节，此处不复列）。**本文件不另立触发点**，以免同一义务在两处漂移。

时点之外，下面的条目适用于任何取证动作，包括你正准备跑的那条确认命令。判不准算不算时按适用处理。

**为什么绑在"外发前"而不是"跑命令前"**：后者在一个跑上百条命令的 session 里等于每分钟触发一次，实测退化成 **0 次打开**（一次 128 条 Bash 的 session 里，本文件被读 0 次）；而"事实要外发了"低频、可识别，且恰好是错了才有代价的那一刻。

**最容易漏的触发形态**，因为你不觉得自己在取证：**把一条并非为该问题而跑的命令的输出读成了结论**——摸底、survey、顺带 dump。此时区分度检查的优先级**更高**，不是更低：那次读数没有为这个结论设计过，你也就没有"我在取证"的自觉。实测的失守全部落在这一类（一条命令并列问三四件不相干的事，输出被略读，其中一段进了决策），而主动跑对照的几次全部发生在已经处于测量循环里的时刻。

这些条目此前住在 `coding-guidelines.md`；那个文件名让人在非编码相位直接判定它不适用，而这几条恰恰在那个相位最常失守。

- 证据要在结论宣称成立的环境里取得：当前 shell、venv 等既存状态是结论的隐藏前提，不是"干净环境 / 全新安装 / 换台机器"的证据。同理，**已在运行的进程**带的是它启动那一刻的环境与代码，而修复常靠"下次启动时加载"生效——"修复已提交"因此不等于"修复已生效"。要断言某个跑着的东西已被修好，证据得取自那个进程（启动时间晚于修复，或直接观察它的当前行为），不是取自仓库；长寿的 tmux pane、daemon、worker 能带着过期环境跑上数天而毫无征兆。
- 据一次检查下结论前，先证明这个仪器报得出**相反**的结局：它报失败 / 空 / null 时，跑一次阳性对照（已知良好条件下它确实报成功）；它报通过时，跑一次阴性对照（预期失败时它确实报失败）。**阴性对照要选对施扰的轴、而且真的越界**：轴要取缺陷**可能所在**的那个，它未必等于断言名义上守的那个量，两者不一致正是下面第二例的失效点；输入则要真能把那个量顶过阈值——被检对象"计数非零"只证明查过了，不证明这次输入够得着阈值（这是本节后面"先断言数量非零"那条的另一半：计数必要而不充分）。实测两例：一条名为「配图不得主导视口」的断言 `max(imgH / innerH) <= 0.4`，上一行就是 `assert media.count() >= 1`、计数这一关是过的，而夹具里 100 多条只有 2 条有图、每条 1 张、图 URL 指向 discard 端口永不加载——于是它在"图确实不主导"与"根本没有配图"两种情况下读数相同。另一例在感知轴上：为音画同步探针施的扰动是"整体时移 +5 s"（检出 −5 s，通过），而缺陷在"时间线断口"轴上，两个探针都把音视频重建成连续流、恰好抹平了那个轴——控制通过 ≠ 对本题材有区分度。阳性与阴性两个方向都有各自的骗法：探针有 bug、读取窗口太小、请求被代理拦截会让健康的对象呈现为坏的；而两种结局下都相同的恒定读数（典型是观测手段自己进了被观测集合）会让坏的呈现为好的。多个本应独立的字段同时为空时，先把"仪器或 scope 取错"当作待证伪的假设，再读成缺陷加剧——但它只是假设：确实存在整片同时为空的真故障。
- **一个已证成立的下游根因不是搜索终止条件。** 同一症状可以有多个成因，而"根因已查清"本身就是一条反向断言（"没有别的原因了"），它没有下游能打脸。真根因带来的满足感恰恰会终止搜索——这比查不出根因更危险：查不出会继续找，查出来就不找了。判据同上一条：**再问一次这个症状，在"只有这一个成因"和"还有别的成因"两种情况下，你手上的读数会不同吗**。实测：唇音不同步查到容器时间戳空洞（真实、已修、已验证）后即收工，从未追问音频源本身是不是产品的那一个——而它确实不是。
- 取证命令的输出会原样进入 transcript、日志和工件，因此凡回显配置、环境或远端状态的读取都先假定它带值输出——`tcb fn detail`、`vercel env`、`env | grep`、`ps eww`，以及 `${VAR:-…}` 这类在变量已设置时展开成值的 shell 构造。只需要存在性时用只产出布尔或计数的写法（`[ -n "$V" ] && echo set`、`grep -c`）；确实需要值时也不整份回显——先取只含名字的脱敏清单（如 `sed -n 's/=.*/=<set>/p'`，`-n`+`p` 不可省：不带它们时多行值的续行不发生替换、被原样放行），再单独取需要的那几个值（能落盘或直接注入下游命令的就不回显进对话）。落盘副本可以事后清除，已进入对话的凭据不能撤回，只能轮换。
- 自己写的机制不要让失败与成功同形。读不到输入就放行、取不到值就返回空串、探测不到就当通过——这类 fail-open 在事后看和"检查通过"完全一样，于是没人会去查。拿不到判断依据时，要么报错，要么把"未能判断"作为一个与通过不同的可观察状态输出。**当场敲的取证命令同样在此列**，它不因为是一次性的就免检：管道的退出码只来自最后一段，`cmd | tail && next` 在 `cmd` 失败时与成功逐字同形，于是 `next` 照跑、其输出被读成对 `cmd` 的确认。要凭退出码判定就用 `set -o pipefail` / `PIPESTATUS`，或把截断与判定拆成两步。**输入为空、循环零次迭代，也会让"没查"打印出与"查过且干净"逐字相同的结果**：变量名写错取到空串后被跳过、列表拆分在当前 shell 下语法不成立于是一次都没进循环——这两种情形下末尾那句 `0 hits` / `全部通过` 与真跑过一遍完全一样。凡是要靠"零命中"下结论的，先断言被检对象的**数量非零**（取到几个键、迭代了几次、实际执行到几条断言），再报结果；这个计数本身也要打印出来，否则下一个读的人同样分不出两种情形。**你自己搭的判定装置（变异对照、探针、桩）也在这条之内**：它中途被掀翻（`set -e` 撞上一条非零返回、被信号杀）时留下的读数与"跑完了、断言没响"逐字相同，于是结论会写成"这条断言没有区分度"或"这段代码是死的"——归咎被测对象，而坏的是装置；**装置自己的退出码**因此也要进输出。同理，工具自身报的「成功」只覆盖它负责的那一段——入队成功不等于被读到，写入成功不等于写对了地方；**它的成功回执在你关心的那件事成立与否两种情况下若取值相同，那就不是证据**。同形的还有取证现场本身：多棵工作树并存时，跑错树的读数与跑对树的逐字同形——取证前的 cwd 自证见 `concurrent-plan-isolation.md`「代码层的块内 cwd 自证」。**本地端口是这条同形律最常见的一种冒名**：`ssh -L <本地端口>:…` 若那个端口已被别的东西占着，转发会失败或被挤掉，而随后的 `curl` 照样 200、照样返回一份看着合理的内容——那是旧实例、另一个服务或另一个 session 的响应，传输层全绿。实测：本机 8848 上早有一个旧实例在听，据它读到的旧内容差一步就被写成「部署没生效」。三条 invariant（**只约束要保证什么，不规定用哪个实现**——`ControlMaster` 复用时正确的 listener 可能由既有 master 持有，把「pid 必须是刚起的那个」当必备条件会把对的隧道判错）：**转发创建失败必须可观察**（如 `-o ExitOnForwardFailure=yes`，别让它静默退化）；**listener 归属要与本次转发方式一致**（新建就核新进程持有，复用就核那个 master 是指向本次目标的）；**响应必须带能区分目标的身份读数**——版本号、commit、构建标记、内容 sha，任何在「旧的」与「新的」之间取值不同的字段，不能只看状态码。同族的冒名者还有代理、缓存与复用的 socket；网页交付路径另有更严的一份（`remote-web-delivery.md`），本条覆盖它不会加载的纯 operator 侧取证隧道。
- **完成断言的观察通道由交付物的消费者决定，不由哪个读数更好取决定。** 先答两问：这件事做完了给谁用？他通过什么看到它？答案就是取证通道。上游读数与下游属性之间每多一层变换，就多一处它们可以不一致的地方——实测：API 返回"每条 23 个指标键"与页面上"123 条一个数都没有"同时为真，因为**键在值为 null 时存在**。**与上一条的分工**：上一条要求你先怀疑自己的检查，本条不要求任何怀疑，只问消费者是谁；两条都该过的场合，本条通常先拦住。替身是**分层**的——破掉一层（行数→值非空）会产生"我已经严谨过了"的满足感，而下一层（文件→渲染页面）照样漏，实测对照组 4/6 正是停在这里。**"渲染页面"也不是最后一层**：实测再往下还有一层——一轮交付里 28 个 `<video>` 全在 DOM 里（`.mcard`=28、`not_synced`=0、112 个数值读数全部正常），而它们被祖先的 `overflow:hidden` 整块裁掉、用户一个也看不见；页面自己的 `IntersectionObserver` 因同一原因永不触发，`src` 从未挂上。**DOM 查询是站在消费者通道上量的替身**，而且是最难自觉的一层：浏览器已经打开、查询的也确实是真实 DOM。判据要换成用户那一侧成立的量——经全部祖先裁剪后与视口的实际相交、媒体的 `readyState`（测法见 `web-ui-observation.md`「测量技术」）。

  **两问的主语是交付物本身，不是本轮改动**——上面那次失守的清单正是这样跑偏的：那一轮的工作是修指标绑定，于是验收只验指标同步，而那个页面的用途是"浏览评测集＝看视频"，视频一条没验。改动是你带进来的视角，用途是消费者的视角；照前者列清单，漏掉的恰好是他打开后第一件要做的事。
  - **交付一个用户会打开的页面时，报告正文必须带该 URL 的验收读数行**——形如 `page-acceptance <url> --expect 'video=28@ready>=2' → ever_intersected 28/28, ready_ok 28/28, errored 0`（`~/.claude/bin/page-acceptance`，它把上面那层替身变成一条机械读数）。`--expect` 要写的是**这一页的主功能元素**，由用途决定，不由本轮改动决定。这条约束的强制力来自读者：**缺了这行、或行里的 URL 与你交出去的对不上，用户一眼可见**——这是把"我可能忘了查"从静默失败改成可见缺失，而不是又一条只能靠自觉的规矩（它确实**不是**机械闸：无人阻止你不写，正因如此才要让它的缺席显形）。跑不了探针的场景（生产 URL 不得被滚动扫描打扰、页面需登录态等）改为写一行降级声明，说明未核实与差在哪一层。
  - **交付的页面用途是"人读到结果"时**，探针打印的「不覆盖」里那些**"探针全绿而读者看不见"的项是待办、不是免责声明**——遮挡、透明度、visibility 与关系层对齐同属此类（同行的可读性归下一条，感知质量归下面「通道是感知性的」，都不按待办处置）。探针覆盖的是存在与就绪，而这些与功能同级：读者要的东西离他几屏、进入时的那一屏装得下几条完整的、要被并排比较的两个对象共不共基线、渲染内容与它的盒子是否一致、以及元素有没有被盖住或透明掉（本枚举里不适用于这一页的项写 `n/a(<这一页的主内容形态>)`，别硬填也别留空——裸一个 `n/a` 在"确实不适用"与"没量"两种情况下同形）——任一不成立页面就没做到它被建出来要做的事，而它们在探针读数上**全部与正常同形**。所以**与验收读数行（或它跑不了时的降级声明）同段**再写一句 `可见性与关系层：<各一句读数>` 或 `可见性与关系层：未核实（<差在哪一项>）`——缺了这半句与缺验收行一样一眼可见，理由同上一条。**探针跑不了不等于这一层跑不了**：「离几屏」与「一屏装得下几条」依赖进入时的视口（时点见 `web-ui-observation.md`「测量技术」表下那条脚注），其余几项不需要滚动。量法见 `web-ui-observation.md`「测量技术」。实测代价：CSS 写死的 `aspect-ratio` 与产品实际输出不符时逐条读数全绿、28 条片每条都带黑边，并排两个播放器顶边差 48px，第一个视频在 5.94 屏之外——三样都通过了验收行（数字见 `web-ui-observation.md`「测量技术」）。
  - **用途是"给人看"的页面，别把可读性归成"打磨"**——归错了它就不进验收项，这正是上面那次的成因。判据用 `CLAUDE.md`「非功能属性不自行加码」那条：能否语义追溯到用户表达的目标**或约束、或本任务开始前已生效且适用于该环境的契约**（三者取一，缺了后两项会把本该算功能的重新判成非功能）。据此：可读性、答案可达性、并排对象的可比性属**功能**，不合格即交付物没做到它要做的事，不需要问用户；而可读之上的精致程度（字阶档数、圆角族、过渡时长）属非功能，按同一条规则测出来 surface 成 choice，不默默做也不默默跳过。
  - **够不着才退，而「够不着」要具体**：不是「需要账号」就算够不着——已有登录态的浏览器往往完全可达；判据是**此刻这条通道 executor 能不能实际走一遍**。确实走不了（无凭据、需真实设备、消费者尚不存在）时退回上游读数，结论降级为「未核实 + 差在哪一层」。**断言同时指向多个消费者时，要么各自覆盖，要么把断言收窄到已覆盖的那一个**——只验其一却按全体断言，与上游替身是同一个错。 `plan-execution-principles.md` §verify 拆分 允许在下层验证（它同时服务「完整链路必须用户介入」与执行中的分段诊断，本条不与它冲突）：它管怎么拆，本条管**最终那个完成断言**用哪个观察面收口——链路不需用户介入、executor 自己能走完时，不走就是选了更好取的替身。
  - **通道是感知性的（要人耳/人眼判定）时**：口型对不对、声音自不自然、画面好不好看，这类属性没有等价的数值读数，executor 也走不了这条通道。此时**不得用数值代理冒充**——把能机械查的结构事实照常摆出来（媒体侧如容器声明时长与解码内容之差、PTS 断口的位置与累计秒数：实测一次交付里 6 处共 32.24 s 的断口本该是一等事实，却被当成工具口径问题解释掉了），再明说"感知轴未核实"，并把**待看的样本做成可直接播放对比的页面**交用户抽查（呈现形态按 `CLAUDE.md`「Present Multimodal Content for User Review」）。要不要为此做全量端到端，成本归用户——经 `AskUserQuestion` 让他定，别自己默默跳过、也别自己默默全做。自建的数值代理同样要按上面「据一次检查下结论前」那条的「施扰的轴要选对」做对照，音画同步探针那个反例就记在那里。
  - **owner 分工**：通用触发与 invariant 在 `CLAUDE.md`「取证的充分性」，方法在本文件；`web-ui-observation.md`（视觉/排版对齐）与 `test-ux.md` §端到端真实使用（该 command 工作流）是**领域特化**、要求更严，不重复通用层判据。
