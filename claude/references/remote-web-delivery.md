# Remote Web Delivery

把 agent 起的网页交到用户手上，且在**用户的机器**上真的打得开。起 server 之前就要读它——下面有几条约束作用在启动时，等到交付才看已经晚了。

执行顺序如下；各小节只展开对应步骤：

**server 已经在跑时**（页面内容变了、或再把链接交给用户）从步骤 2 起，但**必须先按「起 server 时」换一个新 nonce**——那条规则按交付计、不按 server 计。整条流水线以步骤 1 起头，于是"我没有要起的 server"很容易被读成"这套不适用"，或跳过步骤 1 时连带跳过换 nonce；后者静默失败：沿用旧 nonce 会把**上一次交付的点击**算成这一次的回执。

1. 起 server（见「起 server 时」），产出 `<名字>`、日志路径、停止句柄、`<远端端口>` 与本次 `<nonce>`。
2. 拼好 request-target、交付链接与 `--path` 字面量（见「起 server 时」与「端口转发交付」）。
3. 对同一个 request-target 自验正文（见「交付前自验」），产出「已自验到正文」的证据。
4. 自验后立刻取 `BASE`（见「点击回执」），产出清单所需的跨轮状态。
5. 交付统一清单里的六样（见「统一交付清单（不按拓扑分派）」）。

**——轮次边界：以上在本轮完成并交付；以下只能等用户下一次发言。——**

6. 下一轮第一次工具调用，用同一条回执 grep 取 `CUR`（见「点击回执」）。
7. 用 `CUR` 与 `BASE` 做三态判定，产出「回执命中 / 未见 / 无法取得回执」之一。

## 统一交付清单（不按拓扑分派）

**用户的浏览器能否到达这台主机，你观测不到。** `SSH_CONNECTION`、`DISPLAY`、容器标记、乃至"上次问到并存下来的答案"，全都是拿 agent 侧的量代理这个用户侧的事实——历次尝试倒在同一处，换代理量不改变这个结构（`env -u SSH_CONNECTION -u SSH_CLIENT -u SSH_TTY bash -c 'echo ${SSH_CONNECTION:-未设置}'` 一行就能让远端主机报出"我在用户机器上"）。所以不判：交一份在任何拓扑下都成立的东西，再用下面的「点击回执」去读**这一次**的正面证据。逐轮记录与被否理由见 `~/research/ai-agent-config/docs/adr/010-web-delivery-receipt.md`。

**一律交这六样**，不因你觉得自己在哪台机器上而增减。全文只有这一张交付清单，别处提到"一起给"都指回这里：

| 交付物 | 内容 |
|---|---|
| 链接 | `http://127.0.0.1:<本地端口><按「起 server 时」例表拼好的 request-target>` |
| 前置 | `enable-port-forward` 那条命令（见「端口转发交付」）。**措辞不带因果断言**：写「打不开就先跑这条」，不写「打不开说明 server 不在你机器上」——代理、端口占用、命名空间都给同一症状 |
| 退路 | 别的客户端上用的 `ssh -N -L`（见「前提与退路」） |
| 停止 | 停 server 的方式 + 收掉转发 + 删掉 `<日志路径>`，见「端口转发交付」 |
| 边界 | 一句：**已自验到正文**——你在 server 侧 curl 到了本次生成的内容；**用户侧未核实**——用户的浏览器能否到达。这里的「已自验到正文」必须真的通过「交付前自验」那道门 |
| 回执状态 | `<nonce>` / `<日志路径>` / `BASE=<n>`，**外加你实际用的那条 grep pattern**（默认那条可从本文档重建，改过就必须写出来）。算 `CUR` 靠这些；判「未见」前还要按「点击回执」的探针确认 server 仍在记账（**不是**用「停止」行里的句柄——进程在不等于在记账） |

你若真在用户本机，链接直接就能开、那条前置他走不到；代价是一行可忽略的文字，换掉的是交付一条打不开的链接。

唯一的分支来自关于**你自己**的事实（这类该查就查）：**这台主机没有 sshd**（容器 / k8s 常见）时转发命令在这里跑不通——不要编一条跑不通的命令，改用该环境自己的暴露方式；无法自行暴露时如实说明并请用户指定。关于**用户怎么到达你**的事实，仍然不猜。

无 sshd 时仍填同一张六项清单，但用以下替代形态：

| 清单项 | 无 sshd 时怎么填 |
|---|---|
| 链接 | 该环境真实暴露出来的地址，不写 `127.0.0.1:<本地端口>` |
| 前置 | 该环境建立暴露的实际命令或步骤；无法自行暴露时写明需要用户指定，不编 `enable-port-forward` |
| 退路 | 写明 ssh 转发不适用；只给该环境真实可用的另一条入口，没有就如实写没有 |
| 停止 | 停 server 的方式；若暴露机制另有清理动作也一并写，不编 `disable-port-forward` |
| 边界 | 仍写「已自验到正文 / 用户侧未核实」 |
| 回执状态 | 只有真实来源已纳入回执 pattern、且其余回执前提都成立时才写；否则按「点击回执」放弃本次回执，不写这一行 |

不要主动给本机内网地址的链接；唯一例外与它的有效期见文末「绑 0.0.0.0，但不交内网地址」——回执不延长它。

## 起 server 时

- 端口避开 8000 / 8080 / 8888 这类默认口。共享集群（如 DGX）上服务绑 `0.0.0.0`，端口撞车是常态，而"打得开但内容是别人的"是这里最难发现的失败。
- 先定好 `<名字>` 与 `<日志路径>`——三档共用一个你自起的短名 `<名字>`（同时是 tmux session 名与日志文件名）：

  ```bash
  name=<你起的短名>
  logfile="${XDG_STATE_HOME:-$HOME/.local/state}/agent-web/${name}.log"
  mkdir -p "$(dirname "$logfile")"
  ```

  **不要放 `/tmp`**：这份访问日志是下一轮算 `CUR` 的唯一证据，而 `~/.claude/CLAUDE.md`「持久资产与系统临时目录」把验证证据排除在系统临时目录之外——`/tmp` 被清掉时它不可再生，回执就只剩「无法取得回执」。停 server 时连它一起删（写进清单的「停止」行）。

- 用能活过本轮的方式起，并把输出重定向到 `<日志路径>`。三档依次判，判据都是**当场可查的那个命令在不在**，不按系统名猜（多数机器停在第一档；没装 tmux 的机器、精简容器镜像才会往下走）：
  - `command -v tmux` → `tmux new -d -s <名字> '<命令> > <日志路径> 2>&1'`。脱离得最彻底。`-s` 不能省：不给名字时 session 叫 `0`、`1`…，你就没法在交付里告诉用户怎么停它。
  - 否则 `command -v setsid` → `setsid <命令> > <日志路径> 2>&1 < /dev/null & pid=$!`
  - 否则（macOS 即属此列，它没有 `setsid`）→ `nohup <命令> > <日志路径> 2>&1 < /dev/null & pid=$!; disown`。`disown` 必须与前半句在**同一次**命令调用里——job table 是每个 shell 私有的，分两次执行会报 `no current job`。这一档最弱：`nohup` 只忽略 SIGHUP，进程仍留在原进程组，按进程组收割时照样被带走。

  第 2 / 3 档把捕获的 PID 写进交付清单的「停止」行。

  重定向不能省：裸起的 server 其 stdout 仍指向本次工具调用的管道，管道被收走后它每写一行日志都可能吃 SIGPIPE 而死——死得晚且静默，正好绕开这条约束本要解决的问题；日志文件同时是出问题时唯一的排障入口。
- 用户点链接时通常已是你回合结束之后，那时进程必须还在。在之后的某次工具调用里再确认一次（下面的自验 curl 可兼作这次确认）。
- **就在这里生成本次交付的 nonce**，后面的自验与交付都要用它，晚生成就得把自验重跑一遍：

  ```bash
  nonce=$(od -An -tx1 -N4 /dev/urandom | tr -d ' \n')
  ```

  别写成 `tr -dc 'a-z0-9' < /dev/urandom | head -c 8`：`head` 取够字节就关掉管道，`tr` 吃 SIGPIPE，整条赋值返回非零（具体值依实现而异，实测见过 1 与 141）——在 `set -e -o pipefail` 的 shell 里**后面的行直接不执行了**，而 `nonce` 看上去已经生成（实测）。上面这条读固定字节、不靠下游提前关闭，产出 8 个十六进制字符，天然落在 `[a-z0-9]` 里。

  nonce 只能是 `[a-z0-9]`：任何 ERE 元字符（尤其 `+`）或在 query 里会被改写的字符，都会让回执那条 grep 静默算成 0，而 0 与"用户没打开"读数相同。
  nonce 属于**这一次交付**，不属于这个 server：同一个 server 再交付一次（哪怕是同一个页面）就换一个新的，否则上一次的点击会被算成这一次的回执。

  按下面例表把 nonce 接进 request-target；交付链接正文与 `enable-port-forward --path` 都逐字使用右栏，不再另写一套拼法：

  | `<路径>` | 交付链接与 `--path` 里应成为 |
  |---|---|
  | `/report.html` | `/report.html?_rcpt=<nonce>` |
  | `/report.html?tab=2` | `/report.html?tab=2&_rcpt=<nonce>` |
  | `/x#frag?y` | `/x?_rcpt=<nonce>#frag?y`（`#` 后的 `?` 不算 query） |

  路径**已有** `_rcpt` 参数时放弃本次回执；不要改用别的参数名，回执 pattern 里的参数名是写死的，换名会让状态对不上。

## 端口转发交付

这条命令是上面那张清单里的「前置」，每次交付都给。

```bash
enable-port-forward <目标> <远端端口> --path '<按「起 server 时」例表拼好的 request-target>' --open
```

`--path` 必须带上 `_rcpt`，且与你交付出去的链接**逐字符相同**：`--open` 打开的是这条命令自己拼的 URL，`--path` 少了 nonce，用户就算真打开了，回执那条 grep 也永远读不到——机制失效且无声。含 `?` `&` 的路径必须加引号，否则先被 shell 解释掉。

停掉 server 的方式随上面用了哪一档而不同（`tmux kill-session -t <名字>`，或杀掉你记下的 PID）；收掉转发用 `disable-port-forward <本地端口>`，不能漏——不收的转发会一直占着端口，正是下一次撞车的成因。再加一句删掉 `<日志路径>`：它落在持久状态目录里，没人删就一直留着。三样一起写进清单的「停止」行。

链接拼法：`http://127.0.0.1:<本地端口><按「起 server 时」例表拼好的 request-target>`。request-target 自带前导 `/`，这里**不要**再加分隔符，否则拼出 `//`，与命令实际打开的地址不一致。

| 占位符 | 怎么填 |
|---|---|
| `<目标>` | 用户在他那台机器上连本主机所用的名字。DGX 节点上 `hostname -s` 即是；其它环境给出 `hostname -s` 的值，并请用户按自己的 ssh 配置替换 |
| `<远端端口>` | server 实际监听的端口；交付前自验用它 |
| `<本地端口>` | 交付链接与 `disable-port-forward` 用它；默认与远端相同，就按远端端口填。用户因占用改了 `--local` 时，以命令打印的 URL 为准 |
| `<路径>` | server 视角的原始 URL 路径，以 `/` 开头；按「起 server 时」的例表接入 `_rcpt=<nonce>` 后再作为 `--path` 的完整值。整个值加引号——它必然含 `?` 或 `&`，不加会先被 shell 解释掉 |

本地端口默认与远端相同，被占用时命令会失败并提示改用 `--local`。这发生在你回合结束之后，所以交付文字里要写明：**改了本地端口就以命令打印的那条 URL 为准**，不要再用你给的这条。

## 前提与退路

命令预设两件事：用户 ssh 得到这台主机，且他手上有 `enable-port-forward`（由 system-config 的 zshrc 提供，装在用户的 Mac 上）。按这两条成立来给——用户此刻坐在哪台机器前你无从观测，而这是常态。

同时补一行退路供他在别的客户端上用，配同一条链接：

```bash
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:<本地端口>:127.0.0.1:<远端端口> <目标>
```

左边是**本地端口**、右边是**远端端口**，两者默认相同、写起来像一个值，但它们不是一回事：`--local` 改过本地端口之后，退路必须跟着改左边那个，否则它建起来的转发与你给的链接对不上——终端连着、链接照样打不开。

`ExitOnForwardFailure=yes` 不能省：没有它，本地端口绑不上时 ssh 仍会连上并停在那里，终端看着是连着的，点链接却打不开——正是本文档要消灭的那类失败。它是前台命令，终端要一直开着。

还要说清它不自足：`<目标>` 依赖那台客户端自己的 ssh 配置，而需要跳板或非标准端口的主机（DGX 经中转机接入即是）在没有该配置的机器上光有主机名连不上。这类主机要提示用户补齐他那侧的连接方式，你无法代为提供。

## 交付前自验

**没在正文里认出这次生成的内容就不要交付**；先修 server、端口或路径。清单「边界」里的「已自验到正文」指的就是这一步真的过了。

在本机 curl 你**要交付的那条完整 request-target**（不是根路径），连 `_rcpt=<nonce>` 一起（见「起 server 时」的例表：验的必须是交付出去的那个 request-target，否则"裸路径正常、带 query 的交付 URL 404"这类差异验不出来），并且要看正文：

```bash
curl -sS --noproxy '*' 'http://127.0.0.1:<远端端口><按「起 server 时」例表拼好的 request-target>' | head -c 300
```

这里用**远端端口**（server 监听的那个），而交付给用户的链接用**本地端口**。两者不同不影响回执：HTTP 请求行是 origin-form，只含路径与 query、**不含端口**（实测 `"GET /x.html?_rcpt=ab12cd34 HTTP/1.1"`），所以 `--local` 改了本地端口，日志里那行照旧对得上——别因为端口变了就以为回执失效。

`--noproxy '*'` 不要省：万一你验的是内网地址，集群 shell 导出的 `http_proxy` 会把它接走并挂到超时，看着像 server 没起来。

只取状态码不够——端口上跑着别人的服务时同样返回 200，而那正是本文档里最难发现的失败。要看到的是你刚生成的内容。用 `127.0.0.1` 而非内网地址：转发落在远端回环上，验的要和它同一侧。

前 300 字节全是 `<!DOCTYPE html>` 一类模板、分不出是谁的页面时，改用一个只有你这次生成的内容才有的指纹（标题、某个具体数值）：

```bash
curl -sS --noproxy '*' 'http://127.0.0.1:<远端端口><按「起 server 时」例表拼好的 request-target>' | grep -cF '<这次生成的独有字符串>'
```

`-F` 不能省：指纹里的 `.` `[` `*` `?`（标题、版本号里常见）会被当正则。计数为 0（退出码 1）只说明**没找到指纹**，它分不出"内容不是你的"和"根本没取到"（server 没起来、连不上）——要看 `curl` 的 stderr 才能分开。别把 0 直接读成"端口被别人占了"。

stderr 那行 `curl: (23) Failure writing output to destination`（以及开了 `pipefail` 时的非零退出码）是 `head` 取够字节后提前关掉管道造成的，不是自验失败；判据是看到的正文，不是退出码。

上面这一整节只答"内容有没有到"，而它连"到了的这份外壳能不能变成页面"都没答：脚本、样式与字体是另外几个请求，任一 404 都不改变你刚验到的正文，页面却可能整片空白。交的是**给人读的页面**时，还差"人能不能读到结果"——那道门在 `evidence-sufficiency.md`「完成断言的观察通道由交付物的消费者决定」：验收读数行（`~/.claude/bin/page-acceptance`）加上探针不覆盖的那些，逐项归属见该档。**其中 `可见性与关系层` 与 `内容对读者有没有用` 这两格要你自己另起一次浏览器观察**（验收行由探针自己开、自己关，不用你动手；而本节全程是 curl，从没打开过浏览器）；感知质量、可操作性与多状态真实使用另有出口，不由这一次观察结清。

`可见性与关系层` 里属几何的那两项**顺序有讲究**——「离几屏」与「一屏装得下几条」都从**进入时**的视口算起，取晚了就废（时点规则见 `web-ui-observation.md`「测量技术」表下那条脚注）。探针那次滚动不污染你这次：它跑在自己的一次性 session 里。

## 点击回执

上面那份交付里「用户侧未核实」的那一半——用户的浏览器能否到达——你猜不出来，但**用户一点开，server 的访问日志就替他答了**。这是唯一一条来自用户侧、且属于**这一次**的正面证据；它不要求用户说任何话。

点击回执有两个前提：

- **回执判据只对 `python3 -m http.server` 校准过。** 下面那条 grep 逐字咬定它的日志行形状（`<来源IP> - - [时间] "<方法> <target> HTTP/1.1" <状态码> -`）。换别的 server 就先拿它的真实日志核一遍形状再改 pattern；没核就直接用，读数会恒为 0，而 0 与"用户没打开"长得一模一样——那属于下面的「无法取得回执」，不是「未见」。server 不写请求日志时没有回执可做：交付照旧，清单「回执状态」不写，也不宣称执行过回执。
- **回执判据假定用户经回环到达。** 无 sshd 环境的 ingress / `kubectl port-forward`，以及本机内网地址例外，来源都可能不是回环；先按真实来源改 pattern，或直接放弃本次回执。不得让结构性不可见的访问落进「未见」。

依次做三步：

1. **拼法**：nonce 在「起 server 时」已经生成；request-target 逐字采用该节的三行例表。路径已有 `_rcpt` 参数时放弃本次回执。
2. **基线**：交付前自验之后**立刻**数一次，这就是基线——自验自己也会在日志里留一行，不减掉它，回执会一直是「命中」：

   ```bash
   BASE=$(grep -cE "^127\.0\.0\.1 .*\"GET [^\"]*_rcpt=<nonce>[^\"]*\" 200 " <日志路径>)
   ```

   四个条件都不能少：

   | 条件 | 排掉什么 |
   |---|---|
   | `^127\.0\.0\.1` | 同内网别人直连内网地址的访问——他打的是同一个路径、同一个 nonce，只有来源不同 |
   | `"GET ` | **`HEAD` 请求**。IM 里粘链接触发的 unfurl 预览、安全网关扫链接、浏览器 prefetch 都只发 HEAD，没有任何人看到页面，日志里却是一行堂堂正正的 ` 200 `（实测：不加这条，一次 `curl -I` 就把计数顶上去）。这是全节唯一会**过报**的口子，措辞兜不住它——"收到一次带该 nonce 的请求并 200 响应"这句话，HEAD 完全符合 |
   | `_rcpt=<nonce>` | 无关请求，以及**上一次交付**的点击（所以 nonce 一次一换） |
   | `200` | 带着同一个 nonce 却 404/500 的那些——实测去掉它，一次 404 就被算成一次送达 |

   取样后立刻检查：`BASE == 0` 说明回执仪器链路是坏的——日志没落盘、pattern 没对上这个 server、或自验没打到这个 server，三者至少一项成立。查明并修好后重取基线再交付；修不好就放弃本次回执：交付照旧，但清单「回执状态」不写，下一轮也不得宣称执行过回执。

   跨轮状态按统一交付清单写入交付文字，除此之外不另存文件。
3. **时点**：回执检查在**下一轮开头**——用户下次发言后你的第一次工具调用。别挂在交付前的自验上：那时 nonce 还没给出去，读数必然是「未见」，而那与真的没打开长得一模一样。同一条 grep 再跑一次，结果记为 `CUR`；pattern 与日志路径逐字符相同，改过 pattern 就连基线一起重取。

| 条件 | 判定 |
|---|---|
| `CUR`、`BASE` 都是整数，`BASE >= 1`，且 `CUR > BASE` | **回执命中** |
| 都是整数，`BASE >= 1`，`CUR == BASE`，**且下面那个探针证明它仍在同一份 `<日志路径>` 里记账** | **未见** |
| 其余一切 | **无法取得回执** |

「无法取得回执」包含三组情况：

- **回执判据没跑成**：`<日志路径>` 不在 / 读不了 / grep 失败。
- **回执判据跑成了但没法比**：`BASE == 0`（见上）/ `CUR < BASE` / 输出非整数 / `BASE` 已丢。
- **判「未见」之前，先证明记账的还是同一个 server**。发一个只用于探活、带唯一标记且**不含 `_rcpt`** 的请求，然后确认它**新增出现在 `<日志路径>` 里**：

  ```bash
  probe=p$(od -An -tx1 -N3 /dev/urandom | tr -d ' \n')
  curl -sS --noproxy '*' --connect-timeout 2 --max-time 5 -o /dev/null \
       "http://127.0.0.1:<远端端口>/?_probe=$probe" || true
  grep -c "_probe=$probe" <日志路径>     # >=1 才算它还在记账
  ```

  三个要点，少一个就白探：**要超时**（没有 `--max-time` 时，一个接受连接却不回响应的进程会把你卡死，永远进不了下面那个出口）；**光看状态码不够**（端口可能已被别的进程接管，它照样回 200——这与本文档「只取状态码不够」是同一条道理，所以判据是那行日志、不是那个 200）；**不含 `_rcpt`**，才不会污染计数。别用 `kill -0 <PID>` 或 `tmux has-session` 代替：进程存在不等于在记账，被 `SIGSTOP` 停住的 server 照样让 `kill -0` 返回 0（实测），而它那段时间一行日志都不写。

  **判据只有一个：那行日志有没有新增。** `curl` 自己的退出码不作数——所以上面写了 `|| true`。这不是图省事：`http.server` 在**发送响应体之前**就调用 `log_request`，于是「日志已写、随后传输超时」是真实存在的一种结局（实测 `curl` rc=28、而 `grep` 计数 = 1），此时它明明在记账。日志里找不到那行才算探针没通过 → **归「无法取得回执」，不是「未见」**。

  **这个探针的边界要认**：它只证明**检查这一刻**同一个 server 在记账，证明不了整个观察窗口都没停过——server 若在用户点击时被停住、检查前又恢复，你仍会看到 `CUR == BASE` 加一个健康的探针。所以「未见」的真正含义是「判据跑通了、这一刻仪器正常、而计数没涨」，不是「用户没打开」。

**「未见」与「无法取得回执」对外做同一件事**（都不宣称送达、都不主动打断用户这一轮要问的事），但心里不能混：后者是**仪器没读到**，不是"用户没打开"；仪器坏掉报成用户没动作，正是这里最难发现的失败（被否的分隔标记方案怎么坏的，见 ADR-010）。

**命中只断言这么多**：服务器收到了一次来自 loopback、带该 nonce 的 GET，并以 200 响应。不是"页面渲染成功"，不是"响应体完整送达"，也不是"确实是用户本人"。所以内部叫它「回执命中」，别叫"已送达"。

反过来，**「未见」也不等于没打开**：用户重复点同一条链接时浏览器会带 `If-Modified-Since`，server 回 304，那行不计数（实测）。首次点击是 200，所以首次命中不受影响——但别把后续的"计数没再涨"读成他没再看。

**回执不跨交付继承。** 上次打开过不是这次可达的证据——用户换了网、换了客户端、转发断了，`hostname` 一个字都不会变。**每一次新的网页交付都换一个新 nonce、重新从「用户侧未核实」开始**，无论此前命中过多少次；否则回执自己就变成了「统一交付清单（不按拓扑分派）」开头那个被否掉的代理量。

它在本次交付里的用处只有两个：命中后你可以如实说"这条链接已经被取走过"、不必再重复那句「用户侧未核实」；没命中时你**不得**宣称交付已完成。

## 绑 0.0.0.0，但不交内网地址

`~/.claude/CLAUDE.md` 的「本地 Web Server：绑 0.0.0.0 + 交付可达的链接」要求绑 `0.0.0.0`。端口转发本身只需要远端 `127.0.0.1`，所以在本文档的场景里它看起来多余——但那条规则覆盖的不止这个场景，其代价（同内网内任何人可访问该页面）也已被知情接受。不要"顺手修"成 `127.0.0.1`。

反过来也不要顺着那条规则的理由，把本机内网地址的链接一并给用户：你无从确知用户此刻在哪张网上（开头「统一交付清单（不按拓扑分派）」已立此规），所以默认不给——最初的事故正是拿一个自认为对方可达的地址当交付。"这次我知道他在同一个网里"不是豁免，那恰是当初的判断。只有用户**自己开口**要同网访问时才给，且只对**这一次**交付有效：那张网的事实由他提供、不是你推断出来的，而它随他换网就失效——下一轮不能拿"他上次说过想用手机看"当仍然成立的授权。那一次若要做点击回执，先按真实来源改 pattern；否则直接放弃本次回执，不得把结构性不可见报成「未见」。
