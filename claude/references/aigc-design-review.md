# AIGC 流水线设计 · 共享评审底座

`create-aigc-design` 与 `review-aigc-design` 的共同底座。适用于**多步 AI 生成 / 合成 / 编辑流水线**（图像/视频）——其失败模式是**视觉/感知层的工程痕迹**（断层、鬼影、孔洞、残渣、可见重复、内容漂移、涂抹），而非软件可维护性。软件架构/API 设计不在本平面：撰写走 create-plan，评审走 architect-reviewer。

## 核心视角：算法-视觉-效果层（唯一评审平面）

每个操作即使工程上是 paste / tile / blend / mask，**只关心它在算法层对生成结果的影响**，以及有无预/后处理保证坏影响不发生。范式句：*"拼接两张图"工程上是 paste，但真正要审的是——两图是生成分布的独立采样、无像素对应 → 任何 blend 必出鬼影或断层，除非有机制保证不发生。* 审工程机械（参数名、抽象、耦合）= 审错平面。

## 五条硬纪律（违反即 blocker）

1. **接真实数据实测**：任何品味/阈值/分类假设，落文档前先跑一眼真实像素/素材，不凭想象设定。凭"天空应该淡"设阈值 → 被真实像素（鲜蓝天空高饱和）当场证伪。见记忆 taste-artifacts-need-data-grounding。
2. **能实测优先实测**：评审/设计时把候选算法/阈值**跑在真实像素/素材上**看结果，而非头脑推演。（这条抓到过"分类器 no-op、四资产 97% 全前景"。）
3. **机制变更须重评审**：本 gate 只对被评审的那个流水线机制有效。执行中一旦把机制换成另一种（如 分层合成 → restyle 全源图分块拼接；外绘 → 平铺），旧评审结论**作废**，必须对新机制重跑本 gate——新机制有旧机制没有的失败模式。（这条漏过一次："restyle 全源图"是换机制却沿用旧评审，结果 seam 跨店招牌鬼影没被拦。）
4. **验收禁 agent 目视放行**：失败模式验收必须**量化探针**，agent 肉眼反复低估（P6）。且**探针必须对准该失败模式的真实形态**——测错对象=没测（例：seam 鬼影是**羽化带内两独立高频采样的混叠**，测"缝处列阶跃"会漏，须测羽化带内高频内容的双重曝光/错位）。**探针也不得复用实现自身的定义/掩膜**——拿算法验算法 = **循环 oracle**，三项全过也会 bless 破图；探针须独立于实现（锚 ground-truth / 独立参照 / 由评审方另建），作者自建探针不作唯一放行依据（例：rim 足迹探针复用算法的 `sky=L>180` 掩膜验"只碰外轮廓"，全过却放行 68.5% 店内涂抹）。
5. **精细视觉效果烘进源头生成，别事后加到合成图；有失败史的确定性算法默认禁用**：给已合成图**事后添加**一个精细视觉效果（rim-light / 光影 / 描边 / 缝合）**默认致畸，且每条路都不可靠**——模型 edit = 整帧重渲染的亚像素错位色差边 / 鬼影文字；确定性算法 = 分类错致 haze、逐行 argmin 致竖向涂抹、raw-delta 移植致色差鬼影。本项目 rim-light 一个效果连栽四法（`rim_edge` / `auto_rimlight` / `rim_transplant` / `rim_synth`）＋链路A模型 edit，全部致畸。**正确做法：把效果烘进干净源元素的生成里**（exemplar 自带 rim-light 即如此），而非事后 bolt-on。**确定性像素算法：出过问题的默认弃用**（"我只修了发现的那个 bug"反复被证不足），只用已知从未致畸的。全局且内容保持的操作（统一 tone/LUT、resize、锐化）不带接合失败模式，不在此列、可用。要加效果（rim-light、光影、缝合、抠图）**优先走模型**（prompt + exemplar 锚定重生），后处理只作最后手段且限低频区。反复实证：run-010 事后缝、run-012 alpha 抠图、auto_rimlight 逐像素带 **全部致畸**；CP1 / tile 纯模型 restyle **全干净**。设计里任何"事后工程改动模型内容"的步骤，默认按缺陷审、要求作者证明其只碰低频区或改走模型。

## 三层设计模板（create 产出，review 对照）

| 层 | 写什么 |
|---|---|
| **L1** 目标 | 输入(+各自权威性，**含可实测真实素材/地标集的路径**) · 输出 · 验收标准(尤其"1:1 真实尺度人眼无痕"这类目标失败模式) · **必避问题**(从项目历史+已知未解取，每条标 视觉症状/算法根因/出处) |
| **L2** 方案 | pipeline；**每步三写**：操作 → 该操作在算法层对生成结果的影响 → 防护机制。每处"两像素来源相遇"的接合归入下方接合类型学，**只允许 ✅ 类**(出现 ❌ 即设计缺陷) |
| **L3** 论证 | 按下方 7 维 rubric 逐维论证 L2 达成 L1 且不触发必避问题；**显式列自己识别的开放风险** |

## 接合类型学（判每处"两像素来源相遇"）

| 接合类型 | 算法上无断层? | 为什么 |
|---|---|---|
| 同一渲染内部 / 同一采样平铺 | ✅ | 像素同源，无独立采样 |
| 空区外绘（锚定真实像素、mask 区原为空） | ✅ | 新区是以真实邻域为条件的续画 |
| 两独立采样在**纯低频区**(平天空)羽化 | ✅(条件) | 低频微差人眼不可辨——须证明边界确能落在低频区 |
| 语义边界（沿物体自带描边落到背景） | ✅ | 人眼本就期待此处有边 |
| 两独立采样在**含高频内容区**混合/羽化 | ❌ | 无像素对应 → 鬼影或色调/纹理断层 |

## 7 维评审 rubric（review 逐维审，create 逐维自证）

| # | 维度 | 审什么 |
|---|---|---|
| 1 | 接合算法 | 每处接合归哪类？归 ✅ 的是否**真**成立、还是伪装的 ❌ |
| 2 | 分布独立性 | 被混合的两者是否生成分布的独立采样？是→鬼影/断层，除非预处理(共享 conditioning)或后处理(缝藏低频区)保证 |
| 3 | 分类器可分性 | 每个检测/分割步要分的两类，特征分布真的可分吗？**逐真实输入/地标实测**（各类各被判成什么）→ 治孔洞/残渣 |
| 4 | 假设普适性 | 每个结构假设对**所有**输入成立吗？给反例 |
| 5 | conditioning 强度 | 内容保真靠强(真实像素/零重绘)还是弱(文字)？弱→变形 |
| 6 | 验证充分性 | 验收测的是目标失败模式(如 1:1 人眼)还是代理(QA 数字/缩略图)？背离→侥幸过关 |
| 7 | 非干扰 & 周期性 | 修一处扰动他处吗？确定性平铺产生肉眼可见重复吗？ |

## 缺陷判据

只报**设计层**缺陷（换参数救不了、需改设计），不报可调参数。每条：[触发哪个必避问题/新问题][为何是设计缺陷非参数][blocker/major/minor][具体设计层修法]。裁决：**能否进入实现；必须先修哪几个 blocker**。

## 成品放行 gate（BINDING）

**没有任何自动手段能"证明"AIGC 成品干净**——量化探针和独立方 1:1 目视都只是**前置筛，不是成功证明**。
- 量化探针测不到视觉失败模式（"diff 0.2% / 局限在 band 内"≠"看起来干净"，局部化的虚化仍是虚化）。
- 作者自己的眼睛反复低估（P6）+ 确认偏差，**不作放行依据**。
- **独立方 1:1 目视有用但不可靠**：本项目独立 gate 判 v4"条件放行"，用户 1:1 仍见反复出现的老问题——独立目视也会漏。**因此"过了目视 gate"不得等同于"成功"**，只能说"又筛掉了一层"。
放行的真正依据是**用户 1:1 确认**；在此之前一律按"未证明干净"对待，宣告完成前不得声称成品干净。降低对目视兜底的依赖——把可靠性建在**方法**上（下条），而非事后审查上。

## 评审平面边界：算法层 ≠ 风格保真

本评审平面 = **算法层失败模式**（断层/鬼影/孔洞/残渣/重复/漂移）。**风格保真**——生成结果是否匹配 ground-truth exemplar 的**量化风格判据**（如结构性明暗 rim-light、描边、色阶、饱和）——**不在本平面**，本 gate 发现不了它，也不该指望它发现。风格保真需**独立 style-judge gate**：把 exemplar 的风格 rubric 接成生成后每片必过的量化 gate（如 rim_band 亮带幅度阈值），与算法层 gate 分工、不可互相替代。（漏过一次：restyle 把 exemplar 的 rim-light 压平，因无 style-judge gate 且靠目视放行未被拦。）
