# Human-Facing Message Principles

面向人的**状态 / 结果消息**的判据，与投递通道无关。实证来自 push 告警与面向人的终端输出；其它同类通道（web 提示、邮件等）按同一判据类推。

本档同样管**会被人读到的数据契约的字段名与值**（如 artifact 元数据、API 响应、配置、导出格式，完整清单见其通道档）——它们不是"消息"，但读者面对的是同一件事：不去查别处就要能判断这个值意味着什么。实证同样来自那一族契约（不可变注册记录 + 版化 schema + web UI 消费面）。该通道的专属档见下方「各通道专属档」。

**目标**：读者读消息本身即知**受什么影响、该做什么、何时动手**，不必去重推系统已经算出的结论。数据契约通道的等价目标：读者读字段名与值本身即知**这个值意味着什么、能否据它做出他要做的决定**，不必去查 schema 文档、不必猜单位、不必分辨哪个字段权威。

**先定读者情境再套判据**：凡会改变某条判据结论的读者情境差异，先定下来。已知两组落差：

- **读取时上下文是否仍在手**。**默认按"不在手"处理**——消息须完全自解释。只有当通道**结构上保证**读者同步读取（阻塞等待应答的交互式提示、必须当场处置的确认）时才落到"在手"，此时可不重述读者刚做过的事。判据是通道属性，不是"谁发起的"，也不是作者对读取时刻的猜测：同一条输出哪怕由读者亲手敲下，几十分钟后在 scrollback 或 CI 日志里被读到就是"不在手"。
- **读者拿这段内容做什么判断**。粒度是**消息内的段 / 层**，不是整条消息——失败输出的头部供 triage、尾部附诊断 dump 是常见形态，各段分别定标尺。triage 段：只在实现内部有意义的状态量该下沉。诊断 / 测量段（`--verbose`、benchmark、排障 dump）：内部量**不因"仅实现内部有意义"被剔除**，它就是 payload；豁免仅限这一件事，其余判据照旧，只是标尺换成该诊断自身要支持的判断。这一轴的两端方向相反、不存在"更严的一端"，所以**必须判定**——判不准时走下面的逃生阀，不能拿默认值代替判定。

自检：换一种读者情境，我对这段的判决会翻转吗？会 → 该情境要先定下来。

**裁决顺序**：§1–§4 编号小者胜。读者情境层只调节 §1 / §3 / §4 的裁剪幅度，**不减免 §2 的作用域声明义务**——"读者刚做过这件事"不是省略"这个维度本轮没测"的理由。通道专属判据与本档判据正面冲突时本档胜，通道档只能收窄、不能反向放宽；但**通道结构性不可能**（体长硬限的 push / SMS、只能返回 exit code 的通道）不算冲突，按 §3 末段同形处理：通道档记录该限制下的取舍，写明牺牲了哪条判据及理由。可被这样牺牲的只有 §1 / §3 / §4 的裁剪类要求——**§2 的作用域声明义务不在其内**：通道结构上放不下作用域限定时，结论是不在该通道发会让读者得出该结论的消息，而不是发一条无限定的结论。

逃生阀——照上述顺序会与"读者能否据此决策"相悖时，**或读者情境两轴之一判不准时**，构建中先用 `AskUserQuestion` 问用户；纯审查场景（审别人的消息、无提问通道）把两种归档与各自结论一并写进发现清单交消息 owner，不自行裁定。

**保护已达标的表达**：受保护的对象是满足本档**全部**判据的表达；被禁止的动作是**仅由格式统一或判据字面对齐驱动**的重排——例如为凑齐"影响 + 行动"把一句已说清的话拆成三行。

**各通道专属档**（承接本档裁决顺序与逃生阀、不另立）：push 故障告警 → `alerting-review-principles.md`；面向人的 CLI / 安装器 / 脚本 / CI 输出 → `cli-output-review-principles.md`；有人类读者的数据契约字段名与值 → `schema-design-principles.md`。

## 1. 消息自解释

**读消息本身就能知道：什么受影响、该做什么、何时动手。系统已经算出的结论不要让读者再推一遍。**

flag：
- 系统本轮已经算出、读者据以决策却要自己重推的结论没写进消息。归因（"与 pipeline 并发、疑似同机争用"）与**多个同类值里究竟哪个生效**（并列 `stored_mode` 与 `effective_mode` 却不说命中哪个、为何不同）是两个常见形态，不是全集。
- 有下一步，却写成"自己去看"——没有可执行的第一步。
- 读者可能预期需要处置的结果不给动作，也不显式标注"无需动作"——省略与"我漏写了"不可区分。**豁免**：同一决策单位内的同类项（逐条进度、CI 每步 OK、同类事件的连续通知）由该单位的终局结论一次性承载。豁免成立要求终局结论**实际存在且会被读到**，且该项的所需处置与终局结论**同质**——某一项处置发散时（第 7 项成功但降级到 fallback、需事后跟进）它不豁免，或由终局结论显式点出发散项。

自检：把消息给一个只掌握本条消息所处情境下已建立的上下文的读者，他能否说出"影响是 X、我该做 Y、何时"？

## 2. 结论的作用域不超过证据的作用域

**读者据这条消息得出的结论，作用域不得超过本轮真正取得阳性观测的范围——阳性观测指在该维度健康与否两种情况下读数会不同的观测。没拿到阳性观测的维度必须与"已验证健康"可区分，且不能被结论吸收。**

"结论"指**读者会得出的那个**，不限于消息显式写下的那个。消息对某维度沉默、而读者据情境必然代入一个结论时，沉默与写出它同责。

带外信号（退出码、状态字段）替代不了消息里的作用域，除非该通道的契约要求这一类读者读它——**逐读者类判**：同一条 CLI 输出，CI 的契约要求它读退出码，终端前的人没有这个契约，此时该消息对人仍欠一份作用域。

flag：
- 总体结论（**任何档位**，不只是 OK）覆盖了本轮未取得阳性观测的维度，却未声明该维度不在覆盖内。判据是有没有阳性观测——探测失败、数据过期、权限被拒都算没拿到，这不是全集。
- 以阴性观测的措辞冒充阳性结论——"检查通过"表达的其实是"未检查"。
- 限定的可见度低于被限定的结论：声明了作用域，却放在读者主视图之外的位置。
- **消息在"那件事取得了真实读数"与"那件事一次都没发生"两种情况下被读成同一个结论。** 外观不是判据，绿灯与报错同样命中：`0 errors` 既可能是"跑完没错"、也可能是"那段根本没跑到"；一条 `usage: <用法>` 对"这是用法错误"完全诚实，却从未说被查的对象没被查过，实测导致读者据此断定该对象不存在。诚实交代自己那一步的失败因此不满足本条。已经发生的部分要照实说，别为套用本条写出"什么都没做"的假话。
- 维度缺席时不辨来源。缺席的合法性只能由目标自身的显式声明确立（配置里标注该集成可选且当前有意关闭）——"观察到没配置"与配置意外丢失现象完全相同，判不出即按覆盖降级处理。

**边界**：要不要发出这条消息（push 侧的 arm / 推送、CLI 侧的这个档位要不要输出），归通道档；一旦要发，本节的义务就不豁免。

自检：这条结论如果被读者当作"我不用再查了"，会不会漏掉本轮其实没看过、**或看了却分不出该维度是否健康**的东西？沉默地把"没测到"或"分不出"算作"没问题"，比报错更危险。

## 3. 主视图按决策相关性组织

**主视图的预算就是读者的注意力预算：只留读者据以判断的内容，并让需要注意的部分显著。**支撑性细节移到次级位置（evidence / runbook / verbose / 展开态）。本档所称"主视图"由通道档认定哪个流 / 哪个区域。

flag：
- 只在实现内部有意义、读者无从据其决策的状态量（如 `advanced_window_streak=3/3`）出现在主视图。
- 注意力优先级不同的项被等权呈现，读者必须逐行扫才能定位到该先看哪里——正常项与异常项等权、决策相关行与内部计数交错、紧迫度分档不同的异常项之间等权，都是同一失败。

通道没有次级面时（无链接的单条 push、固定长度的通知体），"留在主视图 vs 丢弃"是一个要 surface 的取舍，不默认留下。

自检：主视图里每个片段，读者**决策**时用得上吗？读者能不逐行扫就看出该先处理哪一项吗？

## 4. 值的呈现服从决策用途

**读者不去查别处就能判断这个值意味着什么，且呈现的精细程度与他实际要做的区分一致。**数字、枚举、状态码、模式名同等适用。

flag：
- 缺参照。判据是**逐值**看它有没有自然参照而未给出，不是看它属于哪一类——"3 条源抓取失败"有自然参照（共几源），"发现 3 条新条目"没有，给后者硬造一个分母本身就是违反。
- 呈现的分辨力偏离决策分辨力，两个方向都算：过细（网络延迟 p75 给到亚毫秒 `2367.249083ms`；本地 IPC 或缓存命中耗时的亚毫秒位则正是唯一有信息的位——分辨力由用途定），过粗（紧迫度只给"现在 / 不现在"，而真实处置窗口里还有"下个维护窗口必须处理"）。仅适用于读者真要据其做区分的值。

自检：读者判断这个值是好是坏，缺的参照能在消息里找到吗？他实际要做的区分，和我给的档位或位数一致吗？
