# ADR-018: teammate-reclaim 日志记录「观察到的 transcript 位置」，而非推断出的来源

- 状态：accepted（2026-08-16）
- 决策评审：独立 Codex reviewer，**四轮**。前三轮均未放行（session `01a00b09` 两轮、`01a00b1f` 一轮），第四轮（`01a00ce9`）7/7 成立、无 blocker / 应修 / 无法判断，放行。
- Component：`claude/hooks/teammate-reclaim-check.js` 的日志写入端
- 关系：为 `HARNESS-305` 记录的日志污染提供**将来可分离**的观察位；不触碰 `HARNESS-064` 的 `Stop` 接线决策

## 背景

`~/.claude/logs/teammate-reclaim.jsonl` 把测试夹具与生产记录写进同一文件且无任何标记：149 个 session id 中 **143 个**在 `~/.claude/projects/` 下无现存转录，命名形态为 `caseA-noss` / `ctl-pos-` / `midfligh` 等夹具名。这不是意外泄漏——测试 `R1-F7` 按设计 `statSync(生产 LOG_PATH).size` 取基线再读增量，而 `LOG_PATH`（`:80`）是硬编码常量，连兄弟机制 `judge-log.js:59` 的 `CLAUDE_JUDGE_LOG_PATH` 覆盖旋钮都没有。

**它已实际误导过一次判断**：本轮据该日志算出「只报 idle 桶可消除 54% 的 Stop 期噪声」，后发现那 124 个实例**全部来自夹具**，读数作废。同样地，`HARNESS-064` 否决 `Stop` 接线所引的「实测报出 5 个正在工作的 reviewer」，对应记录也来自一个名为 `midfligh` 的夹具 session——**该取舍两侧都建立在合成数据上**。

## 被否决的备选（前三轮 gate 逐个否掉）

| 备选 | 否决理由 |
|---|---|
| 什么都不改 | 见上：已实际误导过一次 |
| 布尔 `origin` + 消费端默认排除合成 | 判据信号覆盖率仅 27%，会把 **230 个真实 session** 静默判成合成并丢弃 |
| 三值 `origin ∈ {production, synthetic, unknown}` | 两条 blocker：该字段**持续为未来记录**断言来源，而路径惯例不是契约——未来生产若落在临时目录会被**确定地**误标；且无机制能发现**语义**误分类 |
| env 覆盖日志落点（`judge-log.js` 范式） | 本仓已记录该范式失效：`HARNESS-303`「靠"记得设环境变量"这条约定不成立」 |
| 消费端按转录存在性启发式过滤 | 有损：「无现存转录」与「转录已删除的真实 session」同形 |
| 回填历史 143 个疑似夹具 session | 同上，无损判据不存在，回填会把猜测固化成事实 |
| 记录 `source.path` 全文 | 路径含用户目录名，长度不定；本用途只需要一位，记全文是超出需要的留存 |

## 决策

日志每行增加**观察事实**字段 `transcript_under_projects: true | false | null`，由写入端从 `ingest` 回传的 `observedPath`（**本轮**真读到的转录路径）判定：本轮没读到 → `null`；否则该路径是否位于 `~/.claude/projects/` 之下 → `true` / `false`。（**不是** `led.source.path`——理由见下「`null` 的语义」。）

**不做任何来源推断。** 它记录的是「本轮读的 transcript 落在哪里」这一可核验的观察，不是「这条记录是生产还是合成」。后者的解释**推迟到读取时**由消费者做——因为解释可以随认识修正，而写进日志的断言不能。

**本次只写不读**：不改任何消费端行为，不回填历史行。

### 这一框定为何解掉了前三轮的 blocker

前三个方案都在写一个**关于真相的断言**，而证据支持不了它。改成写**可核验的观察**后：

- 未来生产若落在临时目录 → 如实记 `false`。那是**正确的观察**，不是误标 → 解判据 6。
- 不存在「语义误分类」这个类别；字段只会因路径谓词写错而错，而那是确定性的、可逐例断言的 → 解判据 7。

## 作用域

本决策断言的全部内容是：**写入端会如实记录它本轮读到的 transcript 路径是否位于 `~/.claude/projects/` 之下**。

**明确不主张**：

1. 该字段等于「生产 / 合成」——那是读取时的解释，本决策不定义它，也不指定由谁定义。
2. 未来生产 transcript 一定在 `~/.claude/projects/` 下。若不在，字段会如实记 `false`，那是正确的观察。
3. 该字段能让**现有**日志变得可分离——历史行没有它，只有将来新写的行受益；已有的 143 个夹具 session 不可回填。
4. 上面那组 27% 的覆盖率在未来仍成立。

### `null` 的语义

`null` 的语义是**「本轮运行时该 transcript 读不到」**（`transcriptPath` 缺失，或 `statSync` 失败）——这本身是有信息量的观察，不是数据缺失。它也解释了为什么空值区域与「转录已删除的真实 session」高度重合。

**取值必须来自 `ingest` 回传的 `observedPath`，不能来自 `led.source.path`。** 后者是台账里**上一轮**持久化的值：`readNewLines` 的两个提前返回原样退回传入的 `source`，而 `ingest` 无条件 `led.source = source` 再由 `saveLedger` 写回，于是上一次成功读取的路径跨调用存活。拿它当本轮观察，会在一个本轮什么都没读到的行上给出肯定读数——那正是本 ADR 要排除的「用旧轮推断本轮」，会直接击穿上面那条立论。

## 支撑读数

对 `~/.claude/state/teammate-reclaim/` 全部 417 个 state 文件，以「该 sid 在 `~/.claude/projects/` 下有无现存转录」为**有损的参考标签**：

| | 参考标签=真实(337) | 参考标签=夹具(80) |
|---|---:|---:|
| `source.path` 在 `~/.claude/projects/` 下 | 107 | 0 |
| 在 tmpdir 下 | 0 | 7 |
| `source.path` 为空 | 230 | 73 |

在能观察到路径的 114 条上零交叉——说明该观察值**与人们想区分的东西相关**，值得记录供读取时解释。**不主张**它等于来源真值：该参考标签排除不掉「转录已删除的真实 session」。

**本决策的正确性不依赖这组读数**——它只记录观察值，正确性由路径谓词是否写对决定，那是确定性的、可逐例测试的。

## 消费端枚举（放行前完成，双方独立各做一遍）

代码层引用只有：写入 hook 自身（只 append、从不读回）、其单测、以及 `settings.json` 接线；`bg-shell-reclaim-check.js` 仅在注释中提及。`claude/bin/`、`claude/scripts/` 下无引用。**无任何持久读取程序。**

评审者独立复核并给出更强的结论：现有测试消费者 `JSON.parse` 后只检查它需要的字段、**不拒绝额外字段**；且当前 686 行日志**本身已存在 6 种不同字段集合且全部可解析**——读取契约本来就是开放字段集，不存在严格 schema 交界面。

## 已知未验证项

1. 未验证写入端在**所有**事件分支上都会走到落日志那一步。已核对的部分：`SessionStart` 在写日志前返回；当前日志只在实际产生 `UserPromptSubmit` 提醒时写入。故「每行增加字段」不依赖「所有事件都会写日志」这一未经验证的命题。
2. 未验证「`~/.claude/projects/` 是生产 transcript 的唯一根」——但本决策**不依赖**该命题（见作用域 2）。
3. 消费者将来如何解释该字段、由谁定义那套解释，本次不决定。届时那是一个**独立的新决策**，且不会把本字段的既有值变成错误事实。
4. **未核实生产转录在何种情形下会消失或轮转**，因而不知道「本轮读不到」（字段取 `null`）在真实使用中有多常见。这不影响实现正确性——`null` 分支已有确定性用例覆盖——影响的是该字段将来的信息量：若 `null` 极罕见，它接近一个二值观察；若常见，读取方必须认真处理三值。该读数只能在字段积累一段真实数据后取得，本次取不到。

## 前提与已知边界（review-gate 逐出，收窄「只会因谓词写错而错」）

上文「字段只会因这里的路径谓词写错而错」成立**有一个前提**：harness 传入的是**词法形绝对路径**。`path.resolve` 不解 symlink 而 `fs.statSync` 解，所以同一份转录经不同拼法会得到不同读数——本机 `~/.claude` 正是指向本仓 `claude/` 的 symlink，故经实路径 `/Users/lindong/research/ai-agent-config/claude/projects/…` 读到的同一个文件会被记 `false`。同类还有 cwd 依赖：相对路径按 `process.cwd()`（物理路径）解析。

**当前不是活缺陷**：`~/.claude/state/teammate-reclaim/` 下 108 条非空 `source.path` **全部**是词法形、0 条实路径形。但那是观察到的过去，不是 harness 的契约；跨版本或跨平台是否成立未核实。不改实现（`fs.realpathSync` 会引入新的 I/O 失败面，且对已删除的转录会抛）。同理，macOS 默认大小写不敏感，`~/.claude/Projects/…` 能被 `statSync` 读到却判 `false`；不做大小写折叠，那会在 Linux 上引入假阳性。
