# ADR-010：网页交付改用「送达回执」——不再推断用户拓扑，只读本次的正面证据

- 消费者：[`../../claude/references/remote-web-delivery.md`](../../claude/references/remote-web-delivery.md)、[`../../claude/CLAUDE.md`](../../claude/CLAUDE.md) §「本地 Web Server」

## 起因

agent 在远程主机 gpu-box 起了 web server（正确绑了 `0.0.0.0`），交付给用户的却是主机内网 IP `http://10.0.0.23:8123/…`。用户在自己的 MacBook 上按 zshrc 的 `enable-port-forward gpu-box 8123` 建立了转发，仍打不开——转发映射到的是 MacBook 的 loopback，正确链接是 `http://127.0.0.1:8123/…`。

规则本来就在且完整（`CLAUDE.md` §「本地 Web Server」第二段 + `remote-web-delivery.md` 的分派表/链接拼法/四样交付），无任何 hook 强制。所以这不是缺规则。

## 七轮的共同结构（本 ADR 的核心）

| 轮 | 判据 | 否决理由 |
|---|---|---|
| 1 | `agent 不在用户本机时` | 用户否：agent 判不了这个条件。用户原话「一般来说我也不会主动提醒 Claude Code 我是不是在本机」 |
| 2 | `DISPLAY`/`WAYLAND_DISPLAY` 未设置 | 5 blocker：无 sshd 的容器也无该变量；且内联拼法+拓扑判定立第二真相 |
| 3 | 删条件从句、无条件指向 reference | 4 blocker：只把不可观测边界从 CLAUDE.md 下移到 reference 的分派表 |
| 4 | `SSH_CONNECTION`/容器/sshd | 5 blocker：`env -u SSH_CONNECTION -u SSH_CLIENT -u SSH_TTY bash -c 'echo ${SSH_CONNECTION:-未设置}'` 一行即可伪造整张表；且三行不互斥 |
| 5 | 取消分派、链接恒为 loopback、永不给内网 IP | 5 blocker：`--local` 时用的是本地端口（事实错）；绝对禁令与 `:83` 既有一次性例外冲突；「打不开⇒不在你机器上」无区分度 |
| 6 | 问用户一次 + 落盘复用（key=`hostname -s`） | 5 blocker：**stale hit 无症状**——换网/换客户端时 key 不变而正确形态变了 |

1–4 轮换代理量；第 6 轮缓存用户答案——而**缓存也是代理量**（用过去的事实代理此刻的事实）。这五轮全部是**用某个 agent 侧可得的量，代理「用户的浏览器此刻能否到达这个 server」这个用户侧事实**，换代理量不改变这个结构。

第 5 轮是唯一的例外，值得单记：它**取消了分派**、不再需要任何判据，方向是对的，倒在别处——绝对禁令与既有的一次性例外冲突、`--local` 端口的事实错、以及"打不开⇒不在你机器上"这个无区分度的因果断言。第 7 轮的回执正是沿它的方向走完了剩下那半：不判、且补上一条真的读得到的证据。

## 决策

**不再推断，改为读一条本次的正面证据；读不到就 fail-closed，且不做任何因果推断。**

> 本节是**采纳时**的条款原文。落地过程中其中数条被实测推翻或收紧（判据加了 `"GET `、跨轮状态从三样扩到四样、活性判据两度重做、日志路径迁出 `/tmp`）——**现行判据以下面「实施期发现」各节为准**，权威文本在 `remote-web-delivery.md`。

1. **交付链接带一次性 nonce**：`?_rcpt=<8位随机>`，字符集限 `[a-z0-9]`（任何 ERE 元字符或在 query 里会被改写的字符，都会让回执 grep 静默算成 0——而 0 与"用户没打开"读数相同）。拼法先拆 fragment 再判 query 分隔符：`base` 已含 `?` → 用 `&`，否则 `?`，fragment 原样接在最后。路径已有 `_rcpt` 参数 → 放弃本次回执（不换参数名——判据里的参数名是写死的）。
2. **自验就验交付出去的那个 request-target 本身**（同一个 nonce，路径与 query 逐字符相同）——`remote-web-delivery.md` 本就要求验「要交付的那条完整路径」。自验在 server 主机上用**远端端口**、交付给用户的链接用**本地端口**（默认相同，被占用时以 `enable-port-forward` 打印的为准），端口不进日志的 request line，故基线计数不受影响。**自验不过就不得交付**。自验后立刻取基线：
   `BASE=$(grep -cE "^127\.0\.0\.1 .*\"GET [^\"]*_rcpt=<nonce>[^\"]*\" 200 " <日志>)`
   四个条件缺一不可，`"GET ` 那条是后补的——见下「实施期发现」。
3. **回执检查在下一轮开头**（用户下次发言后的第一次工具调用）。三态，不是两态：

   | 条件 | 判定 |
   |---|---|
   | `CUR`/`BASE` 均为整数，`BASE >= 1`，且 `CUR > BASE` | **回执命中** |
   | 均为整数，`BASE >= 1`，且 `CUR == BASE` | **未见** |
   | 其余一切（**`BASE == 0`**、`CUR < BASE`、文件不存在、无读权限、grep 失败、输出非整数、BASE 已丢失） | **无法取得回执** |

   后两者对外行为相同（都不宣称已送达、都不主动打断），但内部不得混为一谈：**拿不到读数 ≠ 用户没打开**。
   `BASE == 0` 归第三行而非第二行：自验成功必然留下一行匹配的日志，基线为 0 只能说明仪器没在工作。它在**交付前**就能读到，所以是就地停下修仪器的信号，不是下一轮才报的判定——**这是手里现成的阳性对照**。
4. **回执只对本次交付有效，不跨交付继承**。上次打开过不是这次可达的证据——否则回执自身变成新的缓存代理量（第 6 轮被否的同一结构）。
5. **命中的语义上界**：只断言「服务器收到了一次来自 loopback、携带该 nonce 的请求，并以 200 响应」。不断言响应体完整送达、不断言页面渲染成功、不断言打开者身份。内部状态名为「回执命中」，不叫「已送达」。
6. **不新增任何数据载体**：跨轮状态只有 NONCE / 日志路径 / BASE 三样，写在上一轮交付文字里、对话内可读；丢失 → 归「无法取得回执」，且**不得宣称执行过回执**。

配套：`CLAUDE.md` §「本地 Web Server」第二段的条件从句「agent 不在用户本机时」删除，改为无条件——回执在任何拓扑下都要做；触发口同时扩到「或把已在跑的这类 server 的链接（再）交给用户」，否则"同一 server 再交付一次要换新 nonce"这条义务没有任何东西把 agent 送过来，旧 nonce 会把上一次的点击算成这一次的回执。`remote-web-delivery.md` 的分派表不再以「用户怎么到达这台主机」为键（该键与同文件后文「不要试图判断用户怎么到达」自相矛盾）。

## 实施期发现（本 ADR 落地时由 6 个独立 reviewer 报出，30+ 条，此处只记改变了决策内容的）

决策过审不等于产物过审。下面四条不是措辞问题——它们各自会让机制以"看起来在工作"的形态失效，且失效读数都与「用户没打开」同形：

| 发现 | 性质 | 处置 |
|---|---|---|
| **`HEAD` 请求计入命中** | **过报**（唯一的过报口子）。IM 粘链接的 unfurl 预览、安全网关扫链接、浏览器 prefetch 都只发 HEAD，没有人看到页面，日志里却是一行 ` 200 `。**措辞兜不住**——决策 5 那句"收到一次带该 nonce 的请求并 200 响应"，HEAD 完全符合 | 判据加 `"GET ` 条件（实测：不加，一次 `curl -I` 就把计数顶上去） |
| **交付清单漏了跨轮状态那一行** | 清单声明"全文只有这一张"，却不含 nonce / 日志路径 / BASE。照表填的 agent 下一轮必判「无法取得回执」——机制 100% 空转 | 清单补第六项 |
| **命名为「送达回执」的那一节，标题断言了它正文明令禁止的词** | 扫标题的 agent 最自然的输出就是"已取得送达回执"，正是决策 5 要消灭的过度断言 | 更名为**「点击回执」**。本 ADR 标题保留原词作历史记录 |
| **三处可直接复制的链接模板把分隔符写死成 `?`** | 路径形如 `/report.html?tab=2` 时拼出 `?tab=2?_rcpt=`，grep 咬不到 → 恒 0 → 静默失效 | 拼法改为一张跨三种分支的例表，模板处一律指向它 |

另有两处**结构性不可见**的情形被补进作用域（原设计未覆盖）：无 sshd 的容器 / k8s 用户经 ingress 到达、以及内网地址例外生效那一次——两者来源都不是回环，`CUR` 恒不涨而 `BASE >= 1`，会落进「未见」而非「无法取得回执」。处置是先按真实来源改 pattern，或直接放弃本次回执。

第二轮重审又改了三处决策内容，都是只有跑起来才发现的：

| 发现 | 处置 |
|---|---|
| 文档给的 nonce 生成命令 `tr -dc … \| head -c 8` 在 `set -e -o pipefail` 下**返回非零**（`head` 关管道 → `tr` 吃 SIGPIPE），后面的行直接不执行，而 nonce 看上去已经生成 | 改用 `od -An -tx1 -N4 /dev/urandom \| tr -d ' \n'`（读固定字节，不靠下游提前关闭；1000 次抽验全部 rc=0、8 字符、`[a-z0-9]`） |
| 回执日志放 `/tmp` **违反上游「持久资产与系统临时目录」BINDING**——它是算 `CUR` 的唯一证据、且不可再生。"失效时安全降级为「无法取得回执」"只防止错误断言，解除不了 BINDING | 日志移到 `${XDG_STATE_HOME:-$HOME/.local/state}/agent-web/<name>.log`，并把删日志写进交付清单的「停止」行 |
| 判「未见」前用 `kill -0` 查 server 活性**有假阴性**：被 `SIGSTOP` 停住的 server，`kill -0` 返回 0 而它一行日志都不写（实测：正常 200 / SIGSTOP 后 000） | 活性判据改为对**不带 `_rcpt` 的原始路径** curl 一次拿 200（不污染计数）；明令不得用 `kill -0` / `tmux has-session` 代替 |

跨轮状态相应从三样扩到四样：`<nonce>` / `<日志路径>` / `BASE` / **实际使用的 grep pattern**（默认那条可从文档重建，改过必须写出来）。

第三轮重审把上面那个活性判据又推翻了一次——**HTTP 200 证明不了记账的还是同一个 server**（别的进程接管端口照样回 200），而这恰恰违背本文档自己「只取状态码不够」那条。最终判据是：发一个只用于探活、带唯一标记且不含 `_rcpt` 的请求，**确认它新增出现在 `<日志路径>` 里**——用日志本身作身份证明，而不是状态码。三个反例已实测：正常 server 探针留下日志行且不污染计数；端口被不写日志的进程接管时状态码 200 而 probe 计数 0（判据正确拒绝）；接受连接却不回响应的进程被 `--max-time` 兜住（rc=28、5s，不会把流程卡死——原判据没有超时）。

判据**只看那行日志、不看 `curl` 的退出码**：`http.server` 在发送响应体之前就调用 `log_request`，「日志已写、随后传输超时」是真实结局（实测 `curl` rc=28 而 `grep` 计数 = 1），此时它明明在记账。

**这个探针的边界一并写进文档**：它只证明检查那一刻同一个 server 在记账，排除不了观察窗口中途停过（点击时被 `SIGSTOP`、检查前恢复）。所以「未见」的含义被收窄为「判据跑通、这一刻仪器正常、而计数没涨」，不再声称"用户没打开"。

## 被否决的备选

| 备选 | 否决理由 |
|---|---|
| **F. 每次交付都先问，不落盘** | 用户否（拓扑近乎恒定，每次问一个恒定答案）。本方案在「未见」时**退化为 F**，故 F 是下界而非替代 |
| **J. 问一次 + 落盘复用** | 第 6 轮 5 blocker（stale hit 无症状）；用户亦否 |
| **A. 绝对 loopback 不变式** | 第 5 轮 5 blocker |
| **B. 继续找更好的代理量**（1–4 轮） | `env -u` 实测证伪一整类 |
| **D. 上 hook 强制** | (a) [`durable-solution-carriers.md`](../../claude/references/durable-solution-carriers.md) 把 hook 定为「声明式规则**被反复漏掉时**的升级项」，本条 1 次实例；(b) **结构性不可达**——失败发生在 assistant 的交付文本里（写了哪个 URL），那里没有工具调用可拦 |
| **双 nonce**（自验一个、交付一个） | 复核 blocker：假定了「不同随机值语义等价」，而 `v` 可能被应用当版本/路由/缓存参数；且违背 `:61`「验要交付的那条完整路径」 |
| **日志分隔标记**（交付前 `>>` 插一行，只数标记之后） | **本轮实测自证伪**：`http.server` 的 stderr 持有该文件自己的 fd 偏移，追加的行被 server 后续写入覆盖 → 回执**恒为 0**，而 0 与「用户没打开」读数相同。一个静默失效 |

## 支撑读数（2026-08-12，gpu-box）

端到端四态（`python3 -m http.server 39121`，nonce `q4w8`）：

| 时点 | 计数 | 判定 |
|---|---|---|
| 自验后 | BASE=1 | — |
| 交付后、用户未打开 | 1 | 未见 ✅ |
| 注入同 nonce 的 404 + 同 nonce 但源为内网 `10.0.0.23` | 1 | 未见 ✅（两条干扰均被排除） |
| 用户真的打开 | 2 | 回执命中 ✅ |

区分度对照：去掉 `200` 条件时 404 行会被误算（2 vs 1）——该条件有实际作用。阴性对照（从未用过的 nonce）= 0。自验污染 = 0。

fragment 拼接实测：`/report.html?tab=2` → `&_rcpt=`；`/x#frag?y` → `?_rcpt=q4w8#frag?y`（`#` 后的 `?` 不算 query，正确）。

副产品：`curl` 到内网 IP 会走集群的 `http_proxy` 并挂起，须带 `--noproxy '*'`。

## 作用域（超出即结论不成立）

agent 起的**临时** web server → 交给**用户浏览器**这一场景，且其 HTTP server 写访问日志（含来源与 request line）、日志可读——`remote-web-delivery.md` 的「起 server 时」要求把输出重定向到 `${XDG_STATE_HOME:-$HOME/.local/state}/agent-web/<name>.log`（**不是** `/tmp`，理由见「实施期发现」第二轮那条），故日志可读是既有约束的副产品。

**缺口全部走同一条安全出口**：不写日志的 server、日志格式不同的 server、用户用了别的客户端、server 已停 → 「未见」或「无法取得回执」，**都不宣称已送达、都不主动打断**。这是与第 6 轮的关键区别——第 6 轮的缺口（stale hit）走进的是**不安全**出口（主动发一条错命令）。

不适用：长期/常驻服务、公网发布（走 `publish-demo` skill）。

## 已知未验证项

1. **agent 是否真会执行这套时序 —— 无对照实测，不主张遵循率改善。** 七轮的判据 2 全部挂在这里。本方案的立论不依赖它：新增的是一个**读数**、不是一条禁令；agent 不去 grep → 退化为现状，没有任何分支会因此发出比现状更错的链接。
2. `enable-port-forward --path '…?_rcpt=…' --open` 端到端未测（`--open` 需 macOS，无环境）。读源码：`_pf_valid_path`（`system-config/zshrc:3152`）只要求以 `/` 开头且无空白/控制字符，`?` `#` 均通过；`_pf_url`（`:3150`）直接拼。**读源码不是实测。**
3. 非 `http.server` 的其它 HTTP server 日志格式未测。
4. server 已停、但日志文件仍在时用户才点 —— 未测（该情形由活性探针兜住，归「无法取得回执」）。
5. nonce 对 SPA/带路由页面的副作用未测（自验验的是同一条 URL，故本次交付内可被自验发现；但不构成对该类页面的普遍结论）。
6. 无 macOS、无容器环境可测。
7. **304 使「未见」不等于"没再看"**：用户重复点同一条链接时浏览器带 `If-Modified-Since`，server 回 304，那行不计数（实测）。首次点击是 200，故首次命中不受影响；但"计数没再涨"读不出他有没有再看。
8. **命中不区分打开者身份**：判据只要求来源是回环。在 loopback 判据下第三方要命中需已在本机或已建立转发，剩余风险我判断可忽略——**这是推断，不是读数**。
