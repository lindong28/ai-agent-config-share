# ADR-016：交付页面前的声明锚定验收探针

- 状态：accepted（2026-08-16）；经 decision-review 三轮（含一次换方案后的完整重走），最终由用户裁决 waive 一项 blocker 后放行
- 组件：`claude/bin/page-acceptance`（新增）、`claude/references/evidence-sufficiency.md`、`claude/references/web-ui-observation.md`

## 问题

一轮交付里 28 个 `<video>` 全在 DOM 中（`.mcard`=28、`.casecard`=14、`not_synced`=0、112 个数值读数全部正常），据此宣称页面可用；用户打开后一个视频也看不到。根因是既有 CSS（`.drift-policy-card{height:100%}` 撑满 `.mcard`，后者 `overflow:hidden`）把播放器整块裁到可视区之外——页面自己的 `IntersectionObserver` 因同一原因永不触发，`src` 从未挂上。

**失守不在"没到消费者通道"，而在到了通道之内仍量替身**：上述计数在"渲染正常"与"全被裁掉"两种情况下取值完全相同。四道既有机制无一兜住，各有其结构性理由：

| 机制 | 为什么没兜住 |
|---|---|
| `review-gate` | 审本轮 diff；致病 CSS 是既有代码，不在 diff 里 |
| `evidence-sufficiency` 消费者通道条 | 触发点确实命中、条文也在 CLAUDE.md 内联，规则在场仍失守；其"替身分层"只列到「文件→渲染页面」，而失守在下一层 |
| `web-ui-observation:22` | 可见性判据为 `display!=='none'` + 宽高>阈值，对该元素（`display:block`、372×512）**假通过** |
| `audit-consumer-channel.py` | 实测 `--days 2` 扫 2644 轮只命中 5 条完成断言，**失守那轮不在其中**（措辞不含其 9 个固定短语）；即便命中，其判据"断言前有无浏览器调用"对该轮也为真。已记 HARNESS-215 |

## 决策

1. **新增声明锚定探针** `claude/bin/page-acceptance`：调用方先声明入口 URL 与**这一页的主功能元素及预期条数/就绪阈值**（`--expect 'video=28@ready>=2'`），探针只报声明与实测之差，**不对全 DOM 猜测什么算坏**。字段名即测法（`ever_intersected` / `ready_ok` / `errored`），输出固定附"不覆盖"清单；四种退出：0 通过 / 1 终局失败 / 3 unresolved（只有就绪量短缺、预算耗尽，"没测出来"）/ 2 仪器故障（打开或 eval 失败、读数与声明错位、注入未生效、超时）。一次性 session、只滚动、明写不得对生产环境运行。
2. **报告级约束**：凡交付一个用户会打开的 URL，报告正文必须带该 URL 的读数行；跑不了则写降级声明。强制力来自读者可见——缺行或 URL 对不上，用户一眼可见。
3. **两处判据修正**：`web-ui-observation:22` 的可见性测法改为「经全部祖先裁剪后与视口的非空交集」（其"测量前置条件"定位不变）；`evidence-sufficiency` 的替身分层补最后一层，并写明"给谁用/他通过什么看到"两问的**主语是交付物本身，不是本轮改动**。
4. **感知轴不造仪器**：口型/声音一类属性无等价数值读数，改为"摆出可机械查的结构事实 + 如实标未核实 + 给用户可播放对比页 + 成本经 `AskUserQuestion` 交用户"。附带一条给自建仪器：**阳性对照要沿缺陷可能所在的那个轴施扰**。

## 被否决的备选

| 备选 | 否决理由 |
|---|---|
| 只加文档自查条文 | `decision-review` origin 记载"规则早就在，依旧犯了；再加一条同类自查等于加更多已经失效的东西"；本次实测正属此类 |
| 强制 `/custom:test-ux` | 派发 codex 做完整用户模拟，成本高；用户明确提出成本 tradeoff |
| Stop **判官**闸 | 已被前一次决策评审否掉（payload 只有末条消息，"真看了"与"没看但这么写"输入相同；第六道判官争用后端可致既有闸 fail-open） |
| **无判官的确定性 hook**（用户曾选定，第三轮评审推翻） | 它的量只是"本 session 出现过调用"：坏页转红、调用失败、验的是另一个 URL、验完页面又被改，**都得到同一读数**——与 HARNESS-215 记录的缺陷同病。另有技术事实：探针是经 shell 调的二进制，transcript 里记为 `Bash`（Codex 侧可能是 `exec_command` 等包装），"探针跑没跑"并非纯结构事实，检测它会退回模式匹配 |
| 全 DOM 枚举 + "存在但不可见即失败" | 第二轮评审判为 blocker：分不出真裁剪与折叠区/未打开 modal/虚拟列表/**合法懒加载**——本次失守那页的视频正是合法懒加载，该设计会误报 |
| 调用率日志 / 误报漏报关联 / 扩展到 CLI 与媒体 | 我自己加的脚手架，第二轮评审逐条指出各带来新的未核实面（日志含 URL 的敏感信息、调用率分母无可靠提取规则、反馈关联机制未定、CLI/媒体无合格读数定义）。**用移除承诺而非增加机制来消解**，义务只限 web 页面 |

## 实测对照（这个仪器报得出相反结局的证据）

| 条件 | `found` | `ever_intersected` | `ready_ok` | 退出 |
|---|---:|---:|---:|---|
| 已修复页面（阴性对照） | 28 | **28** | 28 | 0 ✅ |
| 同页注入致病 CSS（阳性对照，`--inject-css '.drift-policy-card, .prompt-stall-card{height:100%!important}'`） | 28 | **2** | 28 | 1 ❌ |
| 非媒体选择器配 ready 阈值（`.mcard=28@ready>=2`） | 28 | 28 | — | 2（仪器故障，非页面读数） |

`found` 在前两行都是 28——正是当初据以宣称"页面正常"的那个量；`ever_intersected` 从 28 掉到 2。
（阳性对照下仍有 2 个进入视口，因为扫描末尾的 `scrollIntoView` 会滚动祖先容器、够到少数元素；
判据是"是否达到声明条数"，2/28 照样转红。）

**终局判定必须把两种量分开**，否则"慢"与"坏"同形：几何量（`found` / `ever_intersected`）在扫描
与 reach 走完、读数不再变化后不会自愈，短缺即终局失败（1）；就绪量（`ready_ok`）是会推进的量，
预算耗尽仍短缺只能报 unresolved（3）。第一版实现没分开，实测把真坏的页面报成了 unresolved。

设计史另一条实测：原实现把滚动与等待放进一次长 eval，**wedge 了 agent-browser daemon**（EAGAIN os error 35）；已改为 Python 侧驱动的短 eval 序列。

## 作用域

探针只覆盖**被声明的**元素、在**被声明的**单一交互状态下的几何相交与媒体就绪；**不覆盖**遮挡、透明度、`visibility`、可读性、可操作性、感知质量、关系层对齐。它不是页面验收合同，不替代 `web-ui-observation`（值/关系/结构、多缩放多主题）与 `test-ux`（真实端到端）。分工：探针 < `web-ui-observation` < `test-ux`。义务只限 web 页面交付，CLI 与媒体不在本次范围。

回退：脚本与文档可近零成本回退；但据其外发过的"页面可用"结论不可近零成本收回，需重跑验收并更正交付状态。

## 已知未验证项与 waive

- **waive（用户裁决带着它落地）**：无机械约束保证探针会被调用。三轮评审证明各机械方案要么测错东西（hook 的"跑过某命令"）、要么需更大机构。缓解是决策 2 的报告可见性——**不是闸**，只是把静默跳过改成可见缺失。用户在看到该弱点后选择此方案。
- `--expect` 的**同源偏差**：同一执行者填写声明并据结果宣告通过；少声明或选窄 selector 仍可得到"忠于声明却不足以支撑交付结论"的绿灯。本决策不声称解决它，只声称严格优于"完全没有声明"；对抗性验证归 `test-ux` 与用户。
- 探针对非视频型页面（表单、长列表、canvas、虚拟滚动）未实测。
- 生产 URL 场景（禁止滚动扫描打扰）走降级声明，该路径未实测。
- 感知轴仍无仪器。
